# 兼收并蓄

这是你的**进料口**。

转发来的、随手记的、刷到一半觉得有点意思的——全都往这儿扔。这本库的唯一职责是**接住**：不整理、不判断、不追问你「这属于哪个项目」。

它刻意和另外两本库分开。理由不是内容不同，是**这三种东西对「被改写」的容忍度完全不同**：这里的东西要保持你收进来时的原样，《以人为本》里是你自己写的字，《赛博永生》里的页面机器随时可以重写。放进同一本库，第三种迟早会去改前两种，而且不报错。

---

## 怎么往里放

**说一句话就行。** 对桌面智能体说：

> 记一下：定价页把年付放在最前面
>
> 收藏这个 https://example.com/article

它不再替你分类。**凡是通过微信发给 Agent、并要求保存到 Obsidian 的内容，都统一追加到这里的 `灵感集.md`。** 一句话、链接、整段转发文字都走同一个入口；分类和消化等你回到 Obsidian 再做。

`剪藏/` 不属于这条快捷收集链路。它只留给浏览器剪藏插件，Agent 不会把微信消息写进去。微信里即便说「写进日记」，在这个快捷收集窗口里也仍先进灵感集，避免入口一边接住、一边擅自替你判断。

### 有一件事它绝不做

**它不会改你的话。** 不润色、不总结、不换措辞、不替你补主语、不加标签。你说的是哪个字，笔记里就是哪个字。

只有两处清洗：把连续空白压成一个空格，以及把全角竖线 `｜` 换成半角 `|`（那个符号在《以人为本》里是人情账本的记号，混进来会被解析成一笔凭空的人情债）。

## 里面有什么

| 位置 | 放什么 |
| --- | --- |
| `灵感集.md` | 微信发给 Agent 并要求保存的一切内容；最新的排在最前面，带日期和时间 |
| `剪藏/` | 只接浏览器剪藏插件保存的网页，不接 Agent 的微信快捷收集 |

微信入口坚持单一路由，是为了把「先接住」做成确定行为；浏览器剪藏保留独立文件，是因为它天然拿得到网页标题、正文结构和来源地址。两条入口按来源分工，不再按 Agent 对内容的主观判断分工。

打开 `灵感集.md`，最上面那块会列出所有还没勾掉的条目，可以直接点复选框勾。下面是完整的历史记录，一条都不会丢。

## 里面的链接

发链接进来的时候，**原样发就行，不用自己排版**。它会把裸地址从句子里搬到下一行：

```markdown
- [ ] 这个视频讲的分层架构很值得看 [[2026-08-16]] 19:33 #口述
    - 🔗 [点击跳转](https://www.bilibili.com/video/BV1xx)
```

只有「整条记录就一个链接、且它在话的末尾」时才另起一行。链接夹在句子中间就地包成 Markdown 链接，因为搬走会留下「发来两个参考 和 ，后者更清楚」这种破句子。

**它不会去访问那个地址取标题。** 取标题要出网，而这套系统对你的承诺是：记录的过程不联网。

---

## 这里的人名不会变成双链

《以人为本》里写日记时，提到的人可以连成 `[[双链]]`。**微信快捷收集写进这里时不会。**

不是偷懒。人物档案住在《以人为本》，跨库的双链是一条永远点不开的死链——看上去记上了，实际在那个人的档案、关键事件和待办里一条都不会出现，而且不报错。宁可记成普通文字。

---

## 这里的东西怎么出去

你自己捞。刷到一条有用的，把它变成《以人为本》里的一个项目或一张卡片，然后就走那边的流程——项目做完归档，自动进《赛博永生》。

这本库不会自己清空，也不催你。它是个筐，不是个待办清单。

## 三本库

| 库 | 谁在写 | 你要做什么 |
| --- | --- | --- |
| **兼收并蓄**（这里） | 智能体记录，不加工 | 想到就说 |
