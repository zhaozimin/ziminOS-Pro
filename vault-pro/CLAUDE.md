# vault-pro/

> L2 | 父级: ../CLAUDE.md

第二版三库系统里，**第一版没有的那部分**笔记库成品。它与 `vault/` 的分工是硬的：`vault/` 是三本库共享的那一份程序与外观资产的唯一出处（ziminOS 插件、Dataview、Style Settings、Minimal 主题、十二个 CSS 片段），仓库里只存在这一份；本目录只装第二版特有的内容与配置。分工这么切，是为了让第一版与第二版永远不会在主题或插件版本上分叉——同一份资产存两遍，迟早只更新其中一遍，而两本库长得不一样这件事没有任何东西会报错。

三个子目录的**名字就是三本库的目录名**，这不是巧合而是事实源：全新安装时它们被原样铺到系统根下，因此「那本库叫什么」这个问题在仓库里只有一个答案。

## 成员清单

以人为本/: 只有一个文件——`.obsidian/plugins/ziminos/edition.json`。它是**叠加件**，铺在 `vault/` 铺开之后，把一本普普通通的第一版笔记库变成三库系统里的工作台。第二版的全部插件功能都由它开关：没有它，归档不写出库单、「待搬运」视图不存在；有了它，插件才知道自己站在三库系统里。它刻意是一个用户看得见、打得开、删得掉的文件——删掉那本库立刻退回第一版行为，不报错也不损坏任何数据。这本库在本目录里只有一个文件，正说明第一版与第二版的工作台是**同一本库**，不是两套东西。
兼收并蓄/: 进料口的成品。微信发给 Agent 且要求保存的内容只有一个落点：`灵感集.md`；`剪藏/` 专供浏览器剪藏插件，Agent 快捷收集不得进入。`灵感集.md` 的**条目形态**与插件生成的那份逐字一致（`- [ ] 原话 [[日期]] 时间`），**版式**同样两侧同源：查询在上、标题在下，最新的一条紧贴标题。本文件与 notectl 的 INSPIRATION_NOTE 逐字节相同，测试钉着；它装 Dataview 但**不装 ziminOS 插件**，`剪藏/` 是空目录，空目录不进 git，由安装契约 mkdir。
赛博永生/: 成品库的成品，也是卡帕西 LLM wiki 三层结构的落地。`CLAUDE.md` 是那三层里的 **The Schema**，同时是本仓库 GEB 分形文档协议的知识版方言——L1/L2/L3 那套已经在代码上跑了很久，卡帕西那三层是同一个形状，只是把对象从代码换成了知识，因此不发明新术语。`20-知识/索引.md` 与 `90-系统/账本.md` 是卡帕西原文点名的两个关键文件：前者是每次 ingest 的第一站，后者是「哪些原料已经提炼过」这个问题的**唯一**答案。用账本回答而不是在原料上打标记，是为了让原料层真的保持不可变——往原料里写一个 ingested 字段，它就不再是当初归档时的那份东西了。它装 ziminOS 插件（「待提炼」视图靠它）但不装 Dataview。`10-原料/` 是空目录，同样由安装契约 mkdir。

它的三层目录名是**中文**（`10-原料` / `20-知识` / `90-系统`），与《以人为本》那本库的 `00-inbox`…`90-system` 刻意不同。判据是两者的来路不同：PARA 那六个是外面世界的既有约定，改名等于让学员查不到资料；这三层是本产品从卡帕西那篇文章长出来的自有结构，没有外部约定要守，而这本库里除了目录名之外每一个词都是中文。数字前缀两边都留着——它保证文件树的顺序稳定，纯中文名会按拼音随机排。

## 一条容易写错的纪律

两份 `edition.json`（《以人为本》的叠加件与《赛博永生》模板里那份，都在本目录）的 `vaults` 必须完全一致，它是系统布局的唯一事实源。《兼收并蓄》不装 ziminOS 插件，也就没有版次标记——此前这里写着「三份」，一个智能体照着验收清单给它凭空补过一份。从第一版升级上来的用户那本库叫什么是他自己当初取的，所以升级模式下安装器要改写这两份里的 `vaults.human`——**改一份漏一份的后果是出库单指向一个不存在的目录**，而那不会报错，只会让搬运在某天悄悄失败。
