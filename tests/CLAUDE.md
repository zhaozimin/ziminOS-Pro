**每一条读 `skill-pro/` 或 `vault-pro/` 的断言都必须先过「这是不是第二版仓库」那道闸，漏一条就卡死整条发布通道。**这不是纪律洁癖，是一次已经发生的事故：v0.22.0 起陆续有三条断言忘了加闸（Eagle 学员指南住 `docs/`、废弃语义那条读 `vault-pro/` 两本库的 appearance、微信快捷收集整份读 `skill-pro/capture/SKILL.md` 且是在顶层读盘、加载即崩连 skip 都来不及），于是 `publish-v1.sh` 的第四道闸——「同步后的目标仓库必须自己跑得过回归」——**从那时起一直在拦，而且拦得一声不响**：第二版这边永远是绿的，没有任何信号说「第一版已经五个版本没更新了」。发现时第一版公开仓库还停在 v0.21.0，距最后一次同步过去了一周。判据沿用本目录早就写下的那条：区分两个仓库的是**交付物**而不是 `src/`（两边逐字节相同）；闸要问「这是不是第二版仓库」而不是「这个文件在不在」，后者会在 `vault-pro/` 改名时静默跳过，把一条本该变红的测试变成一条永远绿的测试。

**这条坑还有第二种形状，v0.30.0 又踩了一次，而且更狠：顶层那行静态 `import`。** `tests/export.mjs` 从 `../docs/export-demo/build.mjs` 静态引入演示页构建器，而 `docs/` 按设计留在第二版——于是第一版仓库拿到的那份文件**连加载都加载不起来**，三十多条与演示页毫无关系的断言一起陪葬，连 skip 的机会都没有。加闸这个动作对它无效：闸写在测试体里，而体根本没来得及执行。因此判据要再收一层——**第二版专属的东西，在会被同步的文件里只能以「可缺席」的形式出现**：路径存在性先判一次，模块按需 `import()`，断言挂 `{ skip: !HAS_DEMO }`。v0.32.0 起 export.mjs 自己钉住这一条：两份测试入口里不许再出现指向 `../docs/` 的顶层 import。

这里收口可以离开 Obsidian/Eagle 真机验证的回归行为。测试直接编译 `src/` 里的 TypeScript 事实源，不维护第二份实现；平台结构检查钉住移动端加载、Bases 相对上下文、Eagle 回环鉴权、伴侣包白名单与 fail-closed 等不能只靠纯函数表达的边界。专业版多出的十一条测试按交付物是否存在自动启用，因此同一入口可用于两个版次。

发布通道那条的判据是反的：不是「清单里的东西都在」，而是「仓库根的每个条目都被 publish-v1.sh 分过类」——新增一个第二版专属的顶层目录却忘了写进 PRO_ONLY，后果是把付费交付物推进公开仓库，而 git、rsync 与脚本自己的防泄漏断言**都不会报错**，因为那个断言只认清单里已经写着的名字。唯一被豁免的根条目是两个打包脚本默认留在仓库根的 `ziminOS-*.zip` 与 `.sha256`：它们被 `.gitignore` 挡着不进任何仓库，而不豁免的后果是打过一次包，下一次 `npm run check` 就红——打包脚本自己第一步就跑回归，于是第二次打包永远打不出来。

另有一类**跨产物**回归是本仓库独有的：它们不验函数，验的是「代码、模板、契约与首页说的是不是同一件事」。钉住它们的理由是同一个——**这类错都不在写错的那一行报错**。路由那条查每一份存在的施工契约是否都在 `AGENTS.md` 的路由表里：第二版落库时它被漏改，于是整整一个版本里智能体都被它无条件送去第一版契约，只装出一本库而且不报错；目录名那条拿插件常量去 `vault-pro/` 的模板与 `skill-pro/SKILL.md` 的 mkdir 行上核对，不一致的表现只是「待提炼」永远显示空；仓库地址那条查两个版次各自取自己那个 Gitee 仓库——第一版契约会把施工源整份克隆到用户机器，指向 pro 仓库等于把付费交付物发给每个免费用户。三条都只能靠读磁盘上的另一份文件才能发现，这正是它们存在的理由：单元测试再多，也测不出两份文档在说相反的话。

contacts.mjs: 客户模块专项回归；先钉住两张内建总控台初始化为 `MOC-人脉.md` / `MOC-客户.md` 且交叉链接同名，并验证旧名存在时兼容寻址不制造悬空链接，再验证客户名录排序、新档案自带答疑块、存量档案补块保持 CRLF 且幂等，以及答疑必须同时经过标签与 frontmatter 客户双链两道门。
capture-skill.mjs: 微信快捷收集契约的跨产物回归；只允许 SKILL 调用 `notectl.py inspiration`，并钉住「剪藏仅浏览器插件使用」，防止后续文案把语义分类悄悄写回来。
export.mjs: 当前笔记导出的纯函数与结构回归；验证画布单边/总像素自适应、PDF 单页尺寸与纵横比、装饰占位符、水印砖的旋转外接矩形与九种落点、风格验形的夹取与回落、依赖锁版及同一长图复用的接线。另钉住两条只能靠读源码发现的架构边界：预览弹窗**不得**出现 MarkdownRenderer（一旦出现，每拖一格滑块就要重解析整篇笔记），以及截图必须发生在「照终值再施一次装饰」之后（否则用户拖完立刻点导出时，拿到的是上一帧）。v0.24.0 起再加两类：装饰层必须**全同步**（出现 await 即判失败——断言只看去掉注释后的源码，因为本仓库的注释恰恰在解释为什么不许有它，第一版就栽在这儿），链接只补 http(s) 协议、`javascript:` 一律判成没填（那串字会原样变成 PDF 里的一个动作），颜色只认十六进制色号，纸的几何里不许再出现夹取区间/写死内边距/按 scrollWidth 加宽这三处旧发明。v0.31.0 再加三条：页边只有一个来源（纸自己的内边距清零、正文栏跟着纸走、量纸宽问 `offsetWidth` 而非含溢出的 `scrollWidth`）、量版面时挑的是第一个**量得到**的元素而不是第一个存在的（编辑态那个宽度为 0 的阅读态 sizer 此前让整条主线一次都没跑过），可点区域只有一套算法（`offsetParent` 一族不许再出现——两套算同一件事，其中 offsetTop 那套把页脚的 y 算了两遍、落到纸外）、正文 href 不许走补协议那条路（否则库内双链会变成 `https://moc数据库代码/`），以及明暗必须真的切界面并在 `release()` 里无条件还回去——那条断言同时把 v0.29.0「绝不动 body 主题类」的旧约束替换掉，因为它护的是一个错的东西，以及 `docs/导出预览交互演示.html` 必须与它的四份源保持一致——那份 HTML 是生成物，回归重新生成一遍与入库字节比对，改了插件却忘了 `npm run demo` 会当场变红。
bases.mjs: Obsidian Bases 专项回归；精确钉住导航状态 Emoji、系统目录递归排除、MOC 的项目文件/附件/全部三视图，并保证自动建容器与手动 MOC 模板同源、项目流转不改写 Base 代码；存量迁移另验旧硬编码/单表/无 Base 三类识别、导航升级、当前版幂等、自定义冲突、两张内建 MOC 的显式排除、差异预览/并发校验显式接线与批处理失败回滚。

packaging.mjs: 分发包专项。它不测插件行为，测「人拿到的那个包、那份说明，和契约、代码说的是不是同一件事」：pack-zip.py 实跑两遍，中文名必须带 UTF-8 标志位、同一份输入必须得到同一个 zip（DOS 时间只精确到偶数秒，断言照实写）；make-v1-package.sh 的包内名字与《第一版手动安装指南》同名，升级文件夹名与 Obsidian 三枚「打开…文件夹」按钮对得上；说明点名的 ziminOS 程序文件恰好是 skill/SKILL.md 升级分支 cp 的那几个，且升级分支不许替换任何 data.json；说明引用的「开荒」「初始化」「开荒完成 ✅」与空库提示是插件真文案，最低 Obsidian 版本取自 manifest；打包只从 HEAD 取料并先与第一版仓库对账；首页给出 `releases/latest`。v0.33.0 的 Windows 真机复盘之后再加四条：两份契约「取法一」找的包名就是两个打包脚本产出的 ASCII 包名、各去各的仓库的发行版（第一版契约里出现第二版的接口即红），第一版包改名归一的两个文件夹是包里真有的；两份契约都写明复盘里撞过的墙（archive、raw、Windows 前置、`WinError 5`、PowerShell 的 TLS 与进度条）与 Obsidian 真实的信任按钮名；第二版验收清单与交付物一致——`vault-pro` 里版次标记的份数就是清单说的份数，随库分发的 Style Settings 配色不被要求删掉；第二版分发包只从 HEAD 取料并断言私有状态。打包工具与指南只住第二版，十条全挂 IS_PRO_REPO 闸，顶层不读任何第二版专属文件。
