# tests/

> L2 | 父级: ../CLAUDE.md

这里收口可以离开 Obsidian 真机验证的回归行为。测试直接编译 `src/` 里的 TypeScript 事实源，不维护第二份实现；平台结构检查只钉住「移动端加载前不引入 Node」这条不能由纯函数表达的边界。专业版多出的三条测试按源文件是否存在自动启用，因此同一入口可用于两个版次。

这里另有四条**跨产物**回归，是本仓库独有的一类：它们不验函数，验的是「代码、模板、契约与首页说的是不是同一件事」。钉住它们的理由是同一个——**这类错都不在写错的那一行报错**。目录名那条拿插件常量去 `vault-pro/` 的模板与 `skill-pro/SKILL.md` 的 mkdir 行上核对，不一致的表现只是「待提炼」永远显示空，因为它去一个不存在的目录里找原料；两条仓库地址的（一条在专业版块内、一条是全局的）禁止安装入口指向第一版仓库或已 403 的 GitHub 地址，错了 clone 照样成功或干脆连不上，报出来的是「仓库不完整」「无法访问」这种听上去像网络抖动的话，于是用户会去重试而不是换地址。路由那条钉的是同一类错里代价最大的一个：`AGENTS.md` 是桌面智能体自动读到的第一份指令，第二版落库时它被漏改，于是整整一个版本里它都在说无条件的「安装请求 → skill/SKILL.md」与「不得创建另一层目录」——后一句恰好把三库布局明令禁止了，拿着第二版指令来的智能体被它劫持成第一版，只装出一本库，而且用户看到的是一个**装好了的**笔记库，只是少了两本。现在的判据是「每一份存在的施工契约都必须出现在路由表里」，再加第三份契约时它会先红。

四条都只能靠读磁盘上的另一份文件才能发现——这正是它们存在的理由：单元测试再多，也测不出两份文档在说相反的话。

## 成员清单

regression.mjs: Node 内建测试入口，用 esbuild 内存编译纯 TypeScript 模块，对本轮审计中会导致静默数据损坏或整体加载失败的边界做最小回归。它也读磁盘上的模板与契约文本，因为「代码与交付物说的是不是同一件事」这个问题无法只靠纯函数回答。
