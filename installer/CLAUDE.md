# installer/

> L2 | 父级: ../CLAUDE.md

把「全新安装」从契约里的散文搬进代码。起因是一份 Windows 新电脑上的真机复盘：智能体逐条执行契约花了二十多分钟，真正装库的几步一次没卡，时间全耗在一台缺工具的电脑上试工具、一条一条地执行几十个步骤。这里把那几十步收进一个确定性程序，智能体只剩「运行一条命令、读结果文件、告诉用户」三件事；装库本身在本机不到一秒，剩下的是下载。

分工只有一条：**启动脚本只准备 Python 与下载，装库的每一个决定都在核心里。** 于是核心不联网、可以在任何机器上离线测试；两个启动脚本各自只做本平台才需要做的事，逻辑不写两遍。两个启动脚本里真正发出下载的调用**各只有一处**（`Invoke-Download` / `fetch`），最多试四次：上线前实测，连续十几次取 raw 都是 200，其间却夹着一次 451——偶发，可落在谁头上，谁就退回二十分钟的逐条执行。升级暂时不在这里——核心判出「已经装过」就返回 `upgrade`，由两份契约里原有的升级分支接手，等这里的升级实现在真机上验证过再搬进来。

## 成员清单

ziminos_install.py: 安装程序核心，Python ≥ 3.9 标准库，第一版单库与第二版三库的全新安装都在这里。三种包形态归一成同一组目录（第一版给人看的 `ziminOS/` + `字体/`、第二版的仓库形态、仓库根本身），判工作区（宽泛目录、源码仓库、不是空的一律拒绝；已经装过的交给升级分支；智能体自己点开头的配置目录不算「不是空的」），铺库、装当前用户的字体（Windows 另登记 HKCU 并通知会话，同名不覆盖、绝不提权），然后把装出来的每个文件与包里那一份逐字节比对。第二版的三本库名从包里的版次标记读，不写死；自检钉住版次标记只有两份且一致。任何一步失败都把这一次写进工作区的东西原样撤掉——安装前那里是空的，撤干净才能换契约里的逐条做法重来。结果写进工作区的 `.ziminos-install-result.json`（点开头，Obsidian 不索引），屏幕上只打一行 ASCII：有的终端与沙箱会吞掉或读错中文，智能体靠文件而不是靠屏幕知道结果。
install.ps1: Windows 启动脚本，Windows PowerShell 5.1 起可用。**全文只有 ASCII**：5.1 按 ANSI 代码页读无 BOM 的 UTF-8 脚本，一个中文字就是一段乱码——所以本文件的头部契约例外地用英文写。它总是用自己缓存在 `%LOCALAPPDATA%\ziminOS` 的便携 Python（新 Windows 上的 `python` 只是跳商店的空壳，用户自己装的可能太旧），嵌入式包从 npmmirror / 华为云 / python.org 三处轮流取、钉死同一个 SHA-256；版本号读 raw 上的 manifest，包与它的 `.sha256` 走 `releases/download`，不碰对未登录请求限流的开放接口。三处 5.1 的坑各有一行对策：关进度条（否则下载慢十倍）、打开 TLS 1.2（否则连不上 Gitee）、原生程序的 stderr 不许触发终止（否则 Python 的一句警告就能让安装中止）；消息一律 `Write-Host`，因为函数里 `Write-Output` 会混进返回值。头部那条一键命令刻意不含 `$`，在 PowerShell、cmd 与 Git Bash 里原样可用。
install.sh: macOS / Linux 启动脚本，只用系统自带的 bash 3.2、curl、tar 与 shasum。Python 先用已有的：没装开发者工具的 Mac 上一运行 `/usr/bin/python3` 就会弹窗，所以先问不弹窗的 `xcode-select -p`；都没有就下载 python-build-standalone 的精简版（npmmirror 优先，两种处理器各钉一个与上游一致的 SHA-256），缓存在 `~/Library/Application Support/ziminOS`。下载一律交给 curl：它走系统证书库，任何一种 Python 都不必再为证书操心。两个测试用的环境变量：`ZIMINOS_INSTALLER_CORE` 用本地核心不下载，`ZIMINOS_FONT_DIR` 把字体装进指定目录。

## 发布纪律

两个启动脚本从 main 上取核心、从发行版上取包，所以 main 上的版本号前进之后要尽快跑两个打包脚本并用 `upload-release.py` 把 zip 与 `.sha256` 一起挂上发行版——在那之前，安装脚本会报「这一版的包还没挂上去」，智能体退回契约里的逐条做法。
