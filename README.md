# ziminOS

> 一句话：一个能自己开荒、管项目、收灵感、读书划线、经营人脉、逐级复盘，而且开箱就好看的 Obsidian 个人知识管理系统。

> **给桌面智能体：** 本仓库有两份互不引用的施工契约，**先分清用户要装哪一版再动手**。
>
> - 用户只说「搭建 Obsidian 笔记库」「安装 ziminOS」，没提三库 / 第二版 / pro → 执行 [`skill/SKILL.md`](skill/SKILL.md)。当前工作区就是最终笔记库；不要询问名称或路径，不要创建子目录，不要在当前工作区克隆本仓库，只把 `vault/` 的内部内容直接铺到工作区根目录。
> - 用户明确提到**三库 / 第二版 / pro** → 执行 [`skill-pro/SKILL.md`](skill-pro/SKILL.md)。那里的当前工作区是**系统根**，不是笔记库，三本库并排建在它里面。
>
> 装错版次的代价不对称：把第一版装成三库，用户会多出两本他没要、也不知道怎么用的库。判断不了就问，不要猜。

## 一分钟安装

先创建一个**空文件夹**并取好名字，再用桌面智能体打开这个文件夹。然后按你要装的版次，把对应的**整段**指令复制给它。

两段别混着用：装错版次不会报错，只会让你得到一套不是你要的东西。

### 第一版 —— 一本笔记库（免费）

```text
请读取并严格执行 https://gitee.com/ziminzhao/zimin-os-v1/blob/main/skill/SKILL.md，把当前工作区原地搭建或升级为我的 Obsidian 个人知识管理系统。当前工作区就是我已经创建并命名的最终笔记库：不要询问名称或安装路径，不要创建子级笔记库，不要把源码仓库克隆到当前工作区。请严格执行 SKILL.md 中的安全检查、安装或升级、验证与清理步骤，完成后告诉我如何用 Obsidian 打开并初始化。
```

安装完成后，直接用 Obsidian 打开**同一个文件夹**。不需要 Node.js，也不需要另行下载插件、主题或字体。

### 第二版 —— 三本笔记库（学员测试中）

```text
请读取并严格执行 https://gitee.com/ziminzhao/ziminos-pro/blob/main/skill-pro/SKILL.md，把当前工作区搭建**或升级**为 ziminOS 第二版三库系统。施工源走「来路二」，仓库地址是 https://gitee.com/ziminzhao/ziminos-pro.git。当前工作区是系统根，不是笔记库：不要询问名称或安装位置，不要在工作区内克隆源码。请严格执行 SKILL.md 中的安装、验证与清理步骤，完成后告诉我怎么用 Obsidian 分别打开这三本库。
```

装完你会在这个文件夹里看到**三个并排的文件夹**：`兼收并蓄`、`以人为本`、`赛博永生`。用 Obsidian 分别打开它们，不是打开外面那一层。三本里只有「以人为本」需要你手动点一次初始化。

**装完先看一眼对不对。** 如果这个文件夹里只出现了一本库，或者直接冒出 `00-inbox`、`01-projects`、`90-system` 这类文件夹，说明智能体执行的是第一版契约——那不是你要的，把这段指令重发一次，并告诉它「按 skill-pro/SKILL.md 装三库，不是 skill/SKILL.md」。

> **旧指令失效**：早前流传的一键指令指向 `github.com/zhaozimin/ziminOS`，那个地址现在访问不到。请改用上面的 Gitee 地址。

## 更新到最新版

**把下面对应版次的这一整段发给智能体。** 用 Agent 打开的位置与当初安装时是同一个文件夹——第一版是你那本笔记库本身，第二版是外面那一层系统根，不是里面三本中的任何一本。

### 第一版 —— 一本笔记库

```text
请读取并严格执行 https://gitee.com/ziminzhao/zimin-os-v1/blob/main/skill/SKILL.md 中「三、原地搭建当前工作区」下的「升级」分支。当前工作区就是我已经装好的 Obsidian 笔记库，这是升级不是全新安装：不要重新铺库，不要询问名称或路径，不要覆盖我的配色、我自己放进 snippets/ 的片段、其他插件的配置和我已经选好的正文字体。必须先完整执行「二、在工作区外取得施工源」（不要把源码克隆进当前工作区），升级后按「五、清理临时施工源」删掉临时源码。最后把升级前后的 ziminOS 版本号一起报给我。任何一步失败就停下来告诉我是哪一步，不要跳过，也不要换别的做法绕过去。
```

### 第二版 —— 三本笔记库

```text
请读取并严格执行 https://gitee.com/ziminzhao/ziminos-pro/blob/main/skill-pro/SKILL.md 中的「三、C 三库系统的日常升级」。当前工作区是已经装好的 ziminOS 三库系统的系统根，这是升级不是安装：不要重新铺库，不要询问名称或位置，不要动我的笔记、配色、我自己放进 snippets/ 的片段与其他插件的配置。必须先完整执行「二、在工作区外取得施工源」（仓库 https://gitee.com/ziminzhao/ziminos-pro.git，克隆到系统临时目录，不要克隆进工作区），再逐条执行 C 模式，然后按「四、验证」核对、按「五、清理」删掉临时源码。最后把升级前后的插件版本号一起报给我。任何一步失败就停下来告诉我是哪一步，不要跳过，也不要换别的做法绕过去。
```

**收到回执先看两个数字。** 它必须报出升级前和升级后的 ziminOS 版本号；只说「已完成」而没有这两个数字，就是没有证据，让它重跑一次。升级不需要先卸载，也不需要装 Node。

### 为什么不是「把安装那段再发一次」

也能用——智能体会自己认出这是升级而不是全新安装，判据是你那个文件夹里已经有 `.obsidian/`（第一版）或已经有三本库（第二版），**你不需要告诉它「这是更新」**。

但那样有三件事留给它判断：读哪份契约、走安装还是升级、有没有真的换掉程序。它平时判得对，可**判错不报错**——最常见的一种是跳过「取得施工源」那一步，于是「更新成施工源的版本」这句话没有对象，整个升级安静地什么都没做，你重启 Obsidian 只看到插件还是旧的，却找不到哪一步失败了。

上面那两段口令不是另一套做法（做法只有契约里那一份，另写一份迟早只改一份而且不报错），它们只做一件事：**把不许猜的地方钉死，并要求它自证真的干了活。**

### 你的东西会不会丢

不会。一句话记住这条边界：**受管的是「程序」，不受管的是「选择」与「状态」。**

| | 升级时怎么处理 |
| --- | --- |
| **你写的每一篇笔记** | **一个字节都不动。** 升级根本不进你的笔记目录 |
| 插件本体、主题、十三个 CSS 片段 | 整份换成新版——这是你要的那部分；新片段首次出现时按新版默认启用一次，之后开关归你 |
| 你在设置页做过的决定（边栏摆了哪几条命令、目录改没改名、灵感落点、微读登录） | **一个字节都不碰。** 它们住在 `data.json` 里，安装器连读都不读 |
| 你自己挑的主题、正文字体、开着或关着的 CSS 片段 | 保留。你关掉某个片段是一次明确表态，升级不替你重新打开 |
| 你自己放进 `snippets/` 的片段、你自己装的其他插件 | 不动、不删、不改名 |
| 属性类型、附件目录、模板目录（`types.json` / `app.json` / `templates.json`） | 只补你缺的，已经调过的一律保留 |
| 日历缓存、最近文件、光标位置 | 保留。丢了也只是少一点便利，不是数据 |

新版本新增的设置项对老库**自动生效**：插件启动时以默认值打底合并你那份存档，所以安装侧根本不需要动它。

### 更新之后

- **不要重新点「初始化」。** 你的库早就开过荒了，再点一次没有意义。
- 想让新插件立刻生效：Obsidian 里重载一次插件即可。
- 如果这次更新带了新字体：必须**完全退出 Obsidian 再打开**——Chromium 只在启动时枚举一次系统字体，「重新加载」不够。

### 一种情况要特别说

如果你当初装第二版时**只装出了一本库**（旧版本有个路由缺陷会把第二版指令劫持成第一版），别直接在那个文件夹上跑第二版指令：智能体会把它当成一本已有的第一版库，把另外两本建到**它外面那一层**去。

那本库里如果还没有你的笔记，最省事的做法是清空文件夹重装。已经写了东西就告诉智能体一声，让它按「从第一版升级」的路子走，并跟你确认新的两本库建在哪儿。

## 换个窗口，怎么让 Agent 认路（第二版）

安装时会在系统根铺下 `CLAUDE.md` 与 `AGENTS.md` 两份**认路文件**。绝大多数桌面智能体打开一个文件夹时会自动读它们，所以正常情况下你**什么都不用说**，直接开口办事就行：

> 记一下：刚想到一个选题……

如果它没读到（有些客户端不自动读），把下面这句发给它——**一句就够**，其余全在那份文件里：

```text
这是我的 ziminOS 三库系统，系统根在 <把你那个文件夹的完整路径粘在这里>。先读它根目录的 CLAUDE.md，然后照里面说的做。
```

> **从手机接进来的直接看下一节。** 那种窗口连工作目录都常常不在系统根上，认路文件根本没机会被读到，需要的不止这一句。

### 万一它连文件都读不到

有些环境不给智能体文件访问权。那就把下面这段整个发过去，它自带了全部必要信息：

```text
我的 ziminOS 三库系统在 <完整路径>，里面并排住着三本 Obsidian 笔记库：兼收并蓄（进料口，只接住不加工）、以人为本（工作台，项目/读书/日历/复盘/人脉/日记）、赛博永生（成品库，已完成项目在这里被编译成知识）。这个文件夹本身不是笔记库。三本库的真实目录名以磁盘为准：扫描系统根的直接子目录，读第一份 .obsidian/plugins/ziminos/edition.json，它的 vaults 是唯一事实源。

你的施工契约在系统根的 .ziminos/skills/ 里，就在本地，不要联网去取：我说「记一下……」读 capture/SKILL.md；我说「提炼」「体检」，或者粘给你一条项目 MOC 的路径，读 distill/SKILL.md。

三条红线：一、我的原话一个字都不许改，不润色不总结不加标签——微信里要求保存到 Obsidian 的内容全部调用 .ziminos/skills/scripts/notectl.py inspiration 写进《兼收并蓄》的灵感集，剪藏只归浏览器插件；二、赛博永生的 10-原料/ 只读，连加个标记都不行，要记「消化过了」记进 90-系统/账本.md；三、不要在系统根里建笔记。

拿不准就问我，不要猜。
```

> **说明白一件事**：这段提示词解决的是「Agent 认不认得路」，不是「Agent 连不连得上你的电脑」。它得**先有你那个文件夹的访问权**才谈得上照做——你在电脑上用桌面智能体打开系统根，或者用能连回本机的远程会话，都可以；纯聊天窗口没有文件权限的话，再好的提示词也办不成事。

**装好之后自检一次**：新开一个会话，打开系统根，只说「记一下：测试」。它不该反问「你的笔记库在哪」。会问就说明认路文件没铺上或者没被读到，用上面那句短的补一次。

## 从手机记一句话（第二版）

上一节那两段是给「换了个窗口」用的。**手机是它的极端情况**：从手机接进来的会话，工作目录常常不在系统根上（有的客户端根本不让你选），那两份认路文件因此读不到——口令在这里不是备选项，是唯一入口。

先说清它不是什么：**手机上那个窗口自己一个字都写不了。** 动笔的是你电脑上那个智能体，手机只是你对它说话的地方。所以有个前提——这个会话得能连回那台电脑，并且拿得到那个文件夹的访问权（手机端的 Claude Code、能连回本机的远程会话都算）。纯聊天 App 没有文件权限，再好的口令也办不成事。

### 一、先在电脑上取一次路径

手机上没法浏览文件夹，路径得在电脑上取。取一次就一直能用：

1. 打开《以人为本》，随便点开一篇笔记。
2. 设置 → ziminOS → **文件** → 「复制哪一种路径」改成**本机完整路径**。
3. 点一下右下角状态栏那串路径（或 `Cmd + P` 搜「复制当前笔记路径」）。
4. 粘出来是 `/Users/你/你的系统/以人为本/00-inbox/灵感集.md` 这样一串，发给自己——微信文件传输助手就行。

**系统根是三本库外面那一层**，也就是 `以人为本` 前面那一截。懒得截也没关系，下面那段口令里已经让它自己截了。

### 二、把这段发给它

每开一个新窗口发一次。存进手机备忘录或输入法的快捷短语，之后就是两下的事。

```text
这是我的 ziminOS 三库系统，系统根在 <把路径粘在这里>。我从手机连过来，这个窗口只干一件事：我说话，你替我记进笔记。（我粘的可能是某一篇笔记的完整路径，真是那样的话，系统根是三本库外面那一层，你自己截。）

动手前先读系统根的 CLAUDE.md，再读 .ziminos/skills/capture/SKILL.md——两份都在本地，不要联网去取。然后用 .ziminos/skills/scripts/notectl.py 跑一次 status，把三本库的位置报给我。报不出来就停下来告诉我卡在哪一步，不要自己去找库，也不要猜路径。

我确认之后，我要求保存到 Obsidian 的每一条消息都按那份契约办：统一调用 notectl.py inspiration 写进《兼收并蓄》的灵感集。不要分类，不要写日记，不要写剪藏；剪藏只归浏览器插件。禁止手写文件，禁止用编辑器直接改我的笔记。

我的原话一个字都不许改——不润色、不总结、不换措辞、不替我补主语、不加标签。写完只回一行回执，别复述我刚说过的话。只有「这条消息是不是要保存」不明确时才问；落点没有第二个答案。
```

### 三、先看它报回来的那三个位置

它第一句该是三本库分别在哪儿，不是「好的，请说」。**那三行是它真连上了你的库的唯一证据**——手机上你看不见文件树，没有这一步，你分不清它是写进去了，还是只是答应得痛快。

对上了就直接开口：

> 记一下：定价页把年付放在最前面
>
> 记一下今天：下午和王磊过了一遍课程大纲

两句都会进《兼收并蓄》的 `灵感集.md`。快捷收集只负责接住，不再因为一句话提到「今天」就改投日记。

### 这段口令只做路由

「是否要保存」「链接怎么排」「怎样保证原话不变」都在 `.ziminos/skills/capture/SKILL.md`。落点不再需要判断：**微信快捷收集只有灵感集一个入口，剪藏只归浏览器插件。**

### 第一版没有这条路

第一版是一本库，里面没有 `notectl.py`。让智能体直接去改 `灵感集.md` 也能改成，但那正是第二条红线要挡的事：顶部那块查询、插入位置、单条格式都是定死的，交给模型每次都可能不一样，写歪了还不报错。

第一版想在手机上记灵感，用 Obsidian 自己就行——手机装 Obsidian、同步你那本库，命令面板搜「记录灵感」。插件本来就跑在手机端，那条命令照常能用。

## 两个版次

上面第一段装的是**第一版**，免费，一直会免费。第二段装的是**第二版**。下面这张表说清两版的差别，免得你装错。

| | 第一版（免费） | 第二版（付费） |
| --- | --- | --- |
| 笔记库 | 一本 | **三本** |
| 项目 / 读书 / 灵感 / 日历 / 复盘 / 人脉 / 排版 / 外观 | 全都有 | 全都有，一模一样 |
| 说句话就记进笔记 | — | 有：灵感、链接、转发内容，统一进《兼收并蓄》的灵感集 |
| 做完的项目自动变成知识 | — | 有：《赛博永生》按卡帕西 LLM wiki 提炼 |
| 安装指令 | 上面第一段 | 上面第二段 |
| 现在怎么拿到 | 公开，直接装 | **学员测试阶段，暂时也公开可装** |

第二版是付费版，但它现在处在**学员测试阶段**：交付物就放在这个公开仓库里，指令复制过去就能装。测试结束后取用方式会变，这一行到时候会跟着改——所以别把「现在能装」当成「一直免费」。

三本库各管一段，判据不是内容不同，是**这三种东西对「被改写」的容忍度完全不同**：

- **兼收并蓄** —— 进料口。转发的、随手想到的，全往这儿扔，机器只接住，一个字都不改。
- **以人为本** —— 工作台。就是第一版那本库，项目、读书、复盘、人脉、日历都在这里，你自己写字的地方。
- **赛博永生** —— 成品库。你做完的项目自动搬进来，由机器编译成一张互相引用的知识网，你在这里只提问和验收。

**第一版的库可以原地升级成第二版**，你现在这本一个文件都不会动——它会成为三库里的「以人为本」，另外两本在它旁边新建。

### AI 在哪里

第一版里 AI 只出现一次：装库那一次，装完就退场。第二版不是这样，所以直说：

| 库 | AI 参与度 |
| --- | --- |
| 兼收并蓄 | 微信快捷收集全部进灵感集，**不分类、不改你的原话** |
| 以人为本 | 你自己与插件工作，微信快捷收集不跨库写日记 |
| 赛博永生 | 全流程——那本来就是它存在的理由 |

**你说的那句话，一个字都不会被改。** 不润色、不总结、不换措辞、不替你补主语、不加标签。只有两处清洗：连续空白压成一个空格，全角竖线换成半角（那个符号是人情账本的记号，混进去会凭空记一笔债）。这条由一个零依赖的脚本执行，不由 AI 执行，并且钉着 31 条回归测试。

## 三个角色

ziminOS 不是一个插件，是三样东西咬合在一起。

```
   你  ──说一句话──▶  桌面智能体  ──读──▶  skill/SKILL.md      （第一版·一本库）
                          │                skill-pro/SKILL.md  （第二版·三本库）
                          │                （施工手册：怎么装、装到哪、什么时候必须停手）
                          │
                          │ 照着装
                          ▼
                      vault/  笔记库成品
                      （学员的「家」：系统配置 + 外观包 + 新手导游）
                          │
                      ├─ ziminos 插件：开荒 · 项目 · 读书 · 灵感 · 中国日历 · 复盘 · 人脉
                      │                排版 · 编辑 · 文件 · 旧版三入口
                          ├─ Dataview：灵感集未完成任务的交互视图
                          ├─ Outliner：列表的快捷键操作与缩进线
                          ├─ Quiet Outline：可搜索、可折叠的大纲面板
                          └─ 外观包：Minimal · Style Settings · 默认配色 · ziminOS CSS
```

**手册**负责把家搭起来，**家**负责收纳，**ziminOS** 负责系统工作流，**Dataview** 负责查询，**Outliner** 与 **Quiet Outline** 负责大纲与列表，**外观包**保持独立运行。它们一起交付；农历换算仅编译进锁版的 MIT 开源库，其他第三方插件与外观资产仍独立交付。

## 管家会干什么

三十八条命令分成十一组，都能按 `Cmd + P` 调用；其中十条默认摆在左侧边栏。中国日历与一次性迁移命令不占默认左侧按钮。核心工作流是：

| 工作流 | 干什么 |
| --- | --- |
| 开荒 | 建 PARA 六个文件夹、模板、导航页和第一个项目 |
| 项目 | 新建项目/领域、登记卡片，完成/暂停/放弃/重启时整体归档或搬回；旧库可预览并升级导航与 MOC 数据库 |
| 读书 | 从豆瓣自动查书目，合并微信读书、Kindle 与 Apple Books 划线，再把值得拓展的内容摘成卡片 |
| 灵感 | 一个输入框记下一句话，默认置顶进入 `00-inbox/灵感集.md` |
| 中国日历 | 年/季/月独立翻页，显示农历、节气、传统节日、法定休/班；点日/周/月/季/年直达对应记录 |
| 复盘 | 日/周/月/季/年五级复盘；打开日记时补齐缺失主题，已写过则不再打扰 |
| 人脉与客户 | 建人脉、记人情；客户档案汇总付费与交付，并自动检索带 `obsidian/QA` 标签且属性链接到该客户的答疑 |
| 编辑 | 选中文字直接粘网址就变成外链；可把粘贴/拖入的图片与附件交给 Eagle，项目/领域/资源/存档笔记按一级容器归入 `项目/容器名`，日记统一归入 `日记`，笔记只留稳定链接；每篇笔记记住上次光标位置；走开后自动整理 Markdown |
| 导出 | 把当前笔记自适应导出为一整张 PNG 或一页 PDF，导出前先在预览里把页眉、页脚、品牌 logo 与水印调到位 |
| 文件浏览器 | 每个文件夹右侧显示里面有多少篇笔记（也可以改成数子文件夹）；侧栏一张「最近文件」清单；状态栏显示当前笔记路径，点一下复制（复制库内路径还是本机完整路径，自己选） |
| 外观 | 一键开关十三个 CSS 外观片段；删除线默认显示为弱化文字 + 淡警示色背景 + 2px 警示色线，里面的双链另以风险底色和边界突出，已断双链再升一级示警 |
| 旧版三入口 | 把 Obsidian 1.6 挪进文件浏览器底下的「切换笔记库 / 帮助 / 设置」请回最左边那一列 |

两个自动行为（可在设置里关）：

- **新卡片自动登记**——在项目/领域目录里点出一张空白笔记，它自己把字段补齐。
- **updated 自动维护**——已有 YAML 的笔记改动后，更新时间自己刷新。

### 客户答疑自动回到客户档案

答疑仍然放在所属领域。只需同时满足两条：标签含 `obsidian/QA`，并且 frontmatter 任一属性值含客户双链（例如 `[[Alex]]`）。客户档案里的「客户答疑（自动）」会按更新时间倒序显示答疑、领域和日期；正文里普通提到客户不算，避免误收。新客户档案天然带这块，老档案升级后运行一次「补齐客户答疑检索」。

### 当前笔记导出

打开笔记后运行「导出当前笔记」，先弹出预览：左边是等比缩小的整张成品，右边是控件，**拖一格就变一格**。页眉与页脚各自可调靠左/居中/靠右与离正文多远；水印可选平铺整篇（裁不掉，适合防转发）或单个落款（安静，适合署名），并可调九宫格落点、字号、横纵间距、倾斜角度与不透明度，全部支持 `{title}`、`{date}`、`{time}` 占位符，留空即关闭。

**品牌 logo**：选一张笔记库里的图片，页眉、页脚与水印三处各自决定放多大——尺寸拖到 0 就是那一处不放。只放 logo 不写字也成立（落款最常见的样子）。三处默认都是 0，所以老库升级之后导出的那张图与升级前一模一样。想先看看它长什么样，可以直接打开 [《导出预览交互演示》](docs/导出预览交互演示.html)：单文件、离线可看，还能拿你自己的 logo 现场试。

左边那张纸**就是**等会儿被拍下来的那一张，不是示意图，所以看见什么就导出什么。格式可选一整张 PNG 或只含一页的自定义长 PDF；插件按渲染后的全文宽高取图，不擅自分页，超长文章会主动降清晰度而不是截掉后半篇（预览顶部如实报出实际清晰度）。点下「导出」时这套风格才会被记住，下次打开就是它——水印是你的品牌，品牌的意思就是每次都一样。桌面端使用系统保存对话框，探不到时回落保存到当前笔记旁边。

### 附件放进 Eagle（macOS / Windows）

学员可直接打开这份完整步骤说明：[《ziminOS × Eagle 附件桥接安装与使用指南》](docs/Eagle附件桥接安装与使用指南.html)。

升级到 v0.22.9 后，打开「设置 → ziminOS → 编辑 → Eagle 附件」，点「显示安装包」，在 Eagle 覆盖安装同版的 `ziminOS-Eagle-Bridge.eagleplugin`，再用伴侣窗口里的 6 位码配对。默认图片、PDF 等都进入 Eagle，Obsidian 只写 `ziminos-eagle://…/{itemId}`。

若图片要继续使用现有图床，保持图床插件启用，再打开「图片不交给 Eagle（交给图床）」。此时单独粘贴/拖入的图片原样放行给图床，PDF、压缩包、音视频等仍进 Eagle。ziminOS 不保存图床地址或密钥；图片与其他附件不要在同一次操作中混合导入。

**升级 v0.22.9 时必须覆盖安装随包附带的同版 Eagle 伴侣。** 新伴侣会在点击时读取附件此刻所属的 Eagle 文件夹，打开该文件夹并选中附件；只升级 Obsidian 端会明确提示旧伴侣，不会把「在全部中显示」误报为完成。

在 `01-projects/容器名/`、`02-areas/容器名/`、`03-resources/容器名/` 或 `04-archives/容器名/` 内的笔记里粘贴附件时，伴侣会自动创建或复用 Eagle 的 `项目/容器名` 两级文件夹。这四棵根都以第一层文件夹为归属，更深的子目录不改变容器名。日/周/月/季/年日记的附件全部进 Eagle 的单一 `日记` 根目录。直接散落在内容根的笔记不猜归属；它们与其他路径继续使用“非项目附件文件夹 ID”，留空则进入未归类区。目录重名有歧义时导入会停止并说明原因，不会随便挑一个文件夹。

阅读模式里普通单击即可在 Eagle 打开。实时预览、源码模式和 YAML 属性区需按 Obsidian 的编辑器规则：macOS 用 `⌘ + 单击`，Windows 用 `Ctrl + 单击`；普通单击留给放置光标和修改属性值。

Eagle 已运行但窗口最小化时，点链接会把主窗口恢复到前台，打开附件当前所在的项目文件夹并选中附件；Eagle 完全退出时，系统原生深链会先启动 Eagle，ziminOS 随后在有界时间内重连伴侣并完成同样的文件夹定位。建议使用 Eagle 4.0 Build 18 或更高。

在**同一个 Eagle 资源库**里移动附件或更换文件夹，`itemId` 不变，Obsidian 链接不用更新；下次点击时会查询新位置并打开新文件夹。切换资源库或移动整个资源库目录时重新配对即可。导入失败不会偷偷退回 Obsidian 本地附件，避免你以为已经进 Eagle、实际库里又留了一份。

这一版只接管今后新粘贴或拖入的附件；已有本地附件不会被自动迁移或删除。

「记录灵感」不需要 QuickAdd。灵感集第一块就是 Dataview 查询：打开笔记时能立即看到并直接勾选全部未完成任务，分组标题会同时显示这篇文件的真实最后更新时间；查询下面是「# 灵感集」标题，再往下是完整历史，最新的一条紧贴标题。设置 → ziminOS → 灵感里，可以改文件夹、笔记名称、定位标题、插入位置和单条格式；格式支持 `{{content}}`、`{{date}}`、`{{time}}`、`{{datetime}}`。v0.18.0 及以前生成的旧灵感集，下次记录灵感时会自动换成这个版式，并补上最后更新分组；只认字节完全相等的系统查询，你自己写的 Dataview 块一个字都不搬。若想一键呼出，再到设置 → 快捷键给它绑定自己顺手的按键。

## 设计红线

这三条是产品的地基，不是可选项：

1. **人主导**——插件的一切写入都由用户的命令或用户创建的文件触发。没有定时器，没有后台轮询。第二版同样成立：口述是你开口触发的，归档是你点的，提炼是你要的；「赛博永生自动识别新内容」里的「自动」是「打开时算一次」，不是后台扫描。
2. **写入你原话的路径上零 AI**——真正要守的是你说的那句话一个字都不许被改。微信快捷收集连语义分类也取消：只判断「要不要保存」，要保存就由确定性脚本追加到灵感集；链接排版与插入位置不交给 AI。插件端同样没有 AI 调用。本机流程同输入同结果，网络只服务读书外部事实与中国日历数据校验。
3. **官方 API 优先**——原则上只用 `obsidian` 包公开 API；三处必要缺口（微信扫码登录、CSS 即时开关、旧版那三个入口）已在 [`CLAUDE.md`](CLAUDE.md) 中按边界、降级与删除方式完整备案，每一处都做到「探不到就降级，绝不抛异常」。第二版的跨库拷贝差一点成为第四处，最后没有：插件只在本库记一张出库单，真正的搬运交给桌面智能体——代价是拷贝不是「点完立刻出现」，而是「下次和它说话时出现」。

**第一版里 AI 只出现一次**：装库那一次，桌面智能体照着 `skill/SKILL.md` 干活，装完就退场。第二版不是这样，上面「AI 在哪里」那张表把它画清楚了。

## 给学员：完整安装步骤

你不需要懂命令行。照着四步做：

1. 先创建一个空文件夹，并给它取好名字。这个名字就是你的个人知识管理系统名称。
2. 用桌面智能体打开这个文件夹，让它在这个文件夹中工作。
3. 复制粘贴上方「一分钟安装」里**对应版次**的那一整段指令。
4. 安装完成后：第一版直接用 Obsidian 打开同一个文件夹；第二版打开的是里面那三个文件夹，一次一本。

智能体不会再问名称或安装路径，也不会创建另一层文件夹。它会在工作区外临时读取仓库，只把真正有用的笔记库内容放进当前文件夹；你不会看到 `src`、`docs`、`package.json` 等开发文件，也不需要安装 Node、QuickAdd 或 Linter。Dataview、Minimal、Style Settings、默认配色、CSS 和四款阅读字体都已在仓库中。之后跟着笔记库里的 `README.md` 走三步，一分钟开荒完成。

请使用 Obsidian 1.13.0 或更高版本。

想学得更系统：**https://edu.zhaozimin.com**

## 给开发者：怎么构建

```bash
npm install
npm run build
```

`npm run build` = `tsc --noEmit`（严格模式类型检查）+ esbuild 打包。产物直接落在 `vault/.obsidian/plugins/ziminos/main.js`——**构建即就位**，没有中间同步脚本，也没有 dist 目录。

开发时用 `npm run dev`，watch 模式 + inline sourcemap，改完文件在 Obsidian 里重载插件即可。

产物**刻意提交入库**（不进 `.gitignore`），这样学员拿到仓库就能直接用，不需要装 Node。

代码规约：TypeScript 严格模式、注释中文、单文件 ≤ 800 行、禁 `console.log`（用户可见反馈一律走 `Notice`）、常量统归 `src/core/constants.ts`。每个业务文件带 GEB L3 头部契约。
