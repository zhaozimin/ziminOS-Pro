# src/modules/ribbon/

> L2 | 父级: ../../CLAUDE.md

左侧边栏模块。它不生产笔记、不报 VaultSeed，只决定 ziminOS 四十二条命令中哪几条成为最左边的按钮。命令面板对零基础学员是隐形的，但一条命令只要点不到，在产品中就等于不存在。

## 成员清单

icons.ts: 全仓库唯一的命令图形事实源。四十三个图形共用 Pikaicons 的 24 格、2 宽描边、圆头圆角语言：三十八个对应命令，另三个不对应任何命令——dock 是设置页「边栏」标签那块带左栏的面板，explorer 是「文件」标签那个文件夹，editing 是「编辑」标签那个文字光标。三个都画那块地方本身而不画它的功能（文件夹上不挂数字），因为把当期功能画进图标，下一件功能进来时图标就开始撒谎。答疑与导出图标只复用现有几何原语，不引入第二套画法；addIcon 注册时同步登记 removeIcon 卸载回调，不在 Obsidian 全局图标库留悬挂名称。
dock.ts: 按命令分组着色的边栏呈现层。它不认识任何具体命令，只读 ctx.commands 的花名册，直接调用其中的回调，不借用未公开的 executeCommandById。

## 只为勾上的命令建按钮

边栏只为勾选命令调用 addRibbonIcon。手机端菜单与桌面「功能区」设置都遍历 leftRibbon.items，一次建齐再藏 DOM 会让那两处永远列着全部三十八条命令。本次会话取消勾选后，已注册按钮以 `.ziminos-ribbon-hidden` 隐藏；下次重载时根本不再创建。手机端因没有桌面边栏反馈，取消勾选时会明示需重载。

Obsidian 自己在 workspace.json 里还有一把 item.hidden 的锁，它比 ziminOS 设置更硬。公开 API 读不到该字段，因此设置页只说明如何回「设置 → 外观 → 功能区」打开，不为它增加非公开 API 依赖。

## 与外部的接线

对上只暴露 registerRibbon(ctx)，并返回一个按当前设置重画的函数交给设置页。它必须在全部命令注册完成后装配，否则花名册上还没有的命令会静默漏摆。删掉本模块，三十八条命令仍可从命令面板调用，只损失边栏按钮与定制图标。

## 边栏上不属于 ziminOS 的那些图标

本模块只管 ziminOS 自己那几个按钮。Obsidian 自带的快速切换、白板、日记、模板、命令面板、数据库归那把
item.hidden 的锁管，而新库第一次打开时它是什么样，由随库交付的 `vault/.obsidian/workspace.json` 种子决定
（v0.37.0）：六个收起，只留关系图谱。种子只含 `left-ribbon` 一个键，键的先后同时决定图标的先后——
`WorkspaceRibbon.load()` 读完隐藏状态之后，正是按 hiddenItems 的键顺序给 items 排的序。

这条路刻意不写进代码：插件去改宿主的工作区状态文件，要么赶在 Obsidian 把内存里那份写回磁盘之前（赌时序），
要么伸手去碰非公开的 leftRibbon（开红线的口子），两条都不值得，而种子在安装那一刻写下，两样都不需要。
脆弱处也说清楚：那些键是 `插件id:界面文案`，随 Obsidian 的界面语言与版本文案变化；对不上时后果只是
「多出几个图标」，不是报错。tests/regression.mjs 钉住种子与本模块的默认清单说同一件事，以及种子确实被 git 跟踪。
