# modules/editing/

> L2 | 父级: ../../CLAUDE.md

编辑模块。它不生产笔记、不注册命令、不画任何界面，管的是你打字时的两件顺手事：**粘贴到选中文字上就变成外链**，和**关掉一篇笔记时的光标位置下次还在**。

它同时是设置页「编辑」那一页的主人：v0.17.0 用户明令把「排版」并了进来（「排版和编辑应该算作一起，它们属于一类」）。判据是**同一个时刻**——粘贴变成链接、光标记住位置发生在你按下键的那一瞬间，排版发生在你离开这一篇之后，三者之间没有一条缝能塞进「这算不算编辑」这个问题。并的是页不是模块：modules/format 仍然独立，它只是把两个设置交给这一页的后半截去画（页内的先后因此是「立刻发生的」在前、「走开之后发生的」在后）。

两件事凑成一个模块而不是各成一个，判据是同一条：它们都不改变库里有什么，只改变你敲键盘时手感对不对。而它们又必须是两个开关——拦截 Cmd+V 和记住光标是两种性质完全不同的授权，一个开关管不了两件事。

参考的两个社区插件都**没有许可证**（`denolehov/obsidian-url-into-selection` 与 `dy-sh/obsidian-remember-cursor-position` 的 MIT 只覆盖后者），因此这里连「打包交付」这个选项都不存在，只能照行为自己写。反过来说这也是好事：两件事加起来不到三百行，全程公开 API，而上游那两份产物是 7.9 KB 与 105 KB。

## 成员清单

pasteLink.ts: 一个 `editor-paste` 监听，四条门槛全满足才动手——开关开着、这次粘贴还没被别人 `preventDefault` 过、编辑器里真的选着字、剪贴板里真的只有一条**带协议**的网址。窄是刻意的：粘贴是全库最频繁的动作之一，一个判断不清的拦截会让人不敢再按 Cmd+V。裸域名（`www.example.com`）一律不认，因为认它只有两条路——原样写进括号得到一个指向库内相对路径的死链，或者替用户补上 `https://`，那是在他没开口时改写他的剪贴板；两条都不如不动，因为不动他看得见发生了什么。选中的文字里有换行时也不做：Markdown 的链接文字不能跨行，而框选一整段再粘网址，想要的多半就是替换。
cursorMemory.ts: 每篇笔记最后一次的光标行列与滚动位置，以及一条纪律——这些位置**不是设置**。它们住在插件目录下自己的 `cursor-positions.json` 里，与日历的 `holiday-cache.json` 同一档。混进 `data.json` 的后果很具体：升级契约承诺 `data.json` 的 SHA-256 前后不变，而一个每次翻笔记都在改的字段会让那条承诺永远验不过。位置只在**离开这一篇**时读一次（那一刻的光标正是下次要回到的地方），因此不需要定时器也不需要轮询。

## 两处判断值得单独记一笔

**恢复光标不能与用户刚点的那一下抢。** 从一条带锚点的双链跳进来时，Obsidian 已经把光标放在那个标题或块上了——那是用户刚刚点的，比「上次离开时在哪」优先。判据做成一句话：只在光标还停在 0 行 0 列（也就是没人给它定过位）时才恢复。

**滚动位置要等一帧。** `setCursor` 之后编辑器往往还没有最终高度，此刻设的滚动值会被随后的重排抹掉，所以滚动那一步走一次 `requestAnimationFrame`。它是一次性的，不是定时器也不是轮询——与 core/codeblock 的防抖同一档待遇。

## 与外部的接线

对上暴露两个装配入口 `registerPasteLink(ctx)` 与 `registerCursorMemory(ctx)`，两个都**不**交回同步函数——这是它与 explorer、appearance、ribbon 三个模块的关键区别：监听与记忆每次触发都现读设置对象，天然看得见新值；需要有人去推一把的永远只是「已经画在屏幕上」的东西，而本模块一个像素都没画。

设置在「编辑」标签里：两个开关在前，「排版」一道小标题带着它的自动开关与九条规则在后，没有高级折叠区。删掉本模块，粘贴回到 Obsidian 自己的行为、光标回到「每次从头开始」，库里一个字节都不会变——那两个状态文件留着也只是两份没人读的 JSON。
