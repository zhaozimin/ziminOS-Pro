# modules/explorer/

> L2 | 父级: ../../CLAUDE.md

文件浏览器模块。它不生产笔记、不进开荒骨架，管的是同一个问题的三个面：**我在哪个文件**（状态栏那一块路径）、**这个文件夹里有多少**（目录树上那些数字）、**我刚才去过哪儿**（侧栏那张最近文件清单）。

三件事凑成一个模块而不是三个，判据是它们合起来才构成一个人对自己库的**位置感**——单独看每一件都像小装饰，合起来才是「我不会在自己的库里迷路」。设置也因此同住一页（「文件」），并只向设置页交回**一个**同步函数：设置页不必知道这个模块内部由几个文件把三样东西画出来。

它存在的理由是这套系统自己的结构。ziminOS 里的文件夹不是杂物箱而是容器——`01-projects` 装的是项目，一个项目文件夹装的是卡片，一本书的文件夹装的是摘出来的划线。于是学员盯着目录树时问的从来是两个问题：**这里面攒了多少篇**，和**我到底有几个项目**。前者是笔记数，后者是子文件夹数，两个都是这棵树自己知道、却从不说出口的事实。

社区插件 File Explorer Note Count 做过同一件事，参考它的是「计数该长在文件夹右侧」这个交互结论，不是它的实现：它读的是文件浏览器视图的 `view.fileItems`，那个字段不在 `obsidian.d.ts` 里。这里改走公开的 `getLeavesOfType` + `View.containerEl`，再往那块 DOM 里找 `.nav-folder-title`——同样是一层宿主假设，但它是主题与 CSS 片段共用的那一层，而不是别人的私有字段。

## 成员清单

四个文件分成两层：count/badge 是文件夹计数那一支（事实层 + 呈现层），recentFiles 与 filePath 各自自成一件。

count.ts: 事实层，零 DOM、零设置、纯函数。一趟自底向上的遍历数完整棵树，交出一张「文件夹路径 → 笔记数 / 子文件夹数 / 其他文件数」的表。建全库的表而不是「谁要显示就现数谁」是复杂度决定的：展开一百个文件夹时后者会把同一篇笔记按祖先层数重复数一遍，前者与展开了几行无关。三个数分开给而不给「该显示的那一个」，因为悬停提示要把三项一起说清，而常驻屏幕的只有一个——取哪一个是呈现层的决定。它刻意**不**排除 90-system：那条纪律服务的是二十二个知识视图（属性示例里的双链是教材不是事实），而这里数的是「这个文件夹里有几个文件」，文件浏览器把 90-system 明摆在屏幕上，给它一个减掉了模板的数字就与用户点开看到的对不上。
recentFiles.ts: 「我刚才在哪几篇里」。清单一行一篇、**只有笔记名**，行高字号颜色全取 Obsidian 自己的 `--nav-item-*` 变量（六个都在 1.13.7 里核实过），于是它与文件树里的一行长一个样，换主题或在 Style Settings 里调过侧栏字号都跟着变。名字下面那行灰色路径 v0.17.0 由用户明令去掉：多一行不需要读的字，这张清单就从「同一棵树的另一种排法」变成了侧栏里另一种控件，而每认一行都要多读一行；完整路径搬进悬停提示——两篇同名时问一句就有，平时不占屏幕。事实住在插件目录下自己的 `recent-files.json`（与光标记忆、节假日缓存同一档：状态不是设置），呈现是右侧栏一个 ItemView。它与日历有一处刻意的不同——**不**随启动自动展开：日历是每天都要看一眼的坐标，而最近文件是找不回某一篇时才想起来的工具，自动占住半个侧栏对不需要它的人就是一次没被请求的界面改动。清单成员永远是「你打开过的」，两种排法（按打开时刻 / 按文件修改时间）只改排序不改成员——一个你从没打开过的文件出现在「最近」里只会让人愣一下。记录留 50 条而只显示设置里那几条，于是把「显示 10」改成「显示 50」立刻就有 50 条，不必从此刻重新攒。
filePath.ts: 「我此刻在哪一篇」。右下角状态栏常驻当前笔记的完整路径，点一下复制。它取的是 `workspace.getActiveFile()` 而不是活动视图里的文件——焦点落在侧栏（比如刚点了最近文件那张清单）时活动视图不是 Markdown 视图，但用户心里「当前这一篇」并没有变。路径这件事有两个出口：状态栏那一块用来**看**，命令「复制当前笔记路径」用来在手机上或收起状态栏之后也能**拿**，两者调同一段复制，因此提示语一字不差。
badge.ts: 文件夹计数的呈现层，也是本模块与 Obsidian 宿主之间唯一的接触面——全库唯一认识 `.nav-folder-title` 与 `data-path` 的地方就是它顶部那四个常量，与调用处同处一个文件（与 appearance/snippets.ts 收窄那处非公开 API 用的是同一条纪律）。它做三件事：找到文件浏览器那块容器、把数字挂到每行文件夹右侧、在树展开收起或文件增删改名时重挂一次。重画由事件驱动并防抖 80ms，没有定时器也没有轮询。

## 两处判断值得单独记一笔

**改名必须单独听 vault 事件。** 树的展开、收起、懒渲染都是子节点变更，观察者看得见；但重命名时 Obsidian 复用同一个 DOM 节点、只改它的 `data-path`，那不是子节点变更——观察者一个字都看不见，而那一行的数字已经是别人的了。所以 `create / delete / rename` 三个事件与 DOM 观察者并存，各自补对方的盲区。

**自己写的数字不能再触发一次重画。** 往 DOM 里写一个数字本身就是一次子节点变更，一次变更排一次重画，重画又写数字。断这个环有两道：其一，变更回调先问「这变化是不是我自己引起的」——判据与 `core/guard.ts` 的 SelfWriteGuard 同形，只是这里连时间窗口都不需要，我们的痕迹都带着 `ziminos-folder-count` 类名；其二，值没变就一个字都不写。第二道单独就能让它收敛，但收敛不等于不该成环。

## 与外部的接线

对上暴露三个装配入口——`registerFolderCount` / `registerRecentFiles` / `registerFilePath`，各自返回一个「按当前设置重画一次」的同步函数，由 main 合成**一个** `syncExplorer` 递给设置页。合成在 main 而不是在模块内部另起一个 index：main 本来就是唯一装配点，而三个文件因此仍然彼此不认识、可以各自删掉。设置页只改设置对象并落盘，无从让已经画在屏幕上的东西自己改口径或自己消失——与外观开关、左侧边栏那两处是同一套填洞手法，依赖图仍是一棵树。

六个设置住在设置页「文件」标签里，分三段：文件夹计数（开不开、数什么、含不含子文件夹）、最近文件（显示几条、怎么排）、状态栏路径（开不开）。它有自己一页的理由是「一个控件撑一整页是把分页做成摆设」的反面——六项分三段，一页看完就不必再往下翻。

两条命令（打开最近文件、复制当前笔记路径）自成一个命令分组「文件」，着靛蓝（找路＝罗盘针的颜色）。它们的存在把装配顺序也定住了：本模块必须排在 ribbon 之前装配，因为边栏是照着命令花名册摆图标的，摆的时候花名册必须已经收齐。

关掉开关与卸载插件走的是同一段清理，因此「关掉」与「卸载」的结果一字不差：DOM 里一个残留节点都没有。删掉本模块，目录树回到 Obsidian 原样，库里没有任何一处需要跟着改。
