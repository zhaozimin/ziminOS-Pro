# src/modules/export/

> L2 | 父级: ../../CLAUDE.md

把当前 Markdown 笔记导出为一整张 PNG 或单页 PDF，导出之前先让用户在真实的纸上把版式调到位。两种格式共用同一份离屏渲染结果：先按当前笔记可见正文宽度建立纸面，再等待 Markdown、ziminOS 代码块、图片与字体稳定，最后按真实 `scrollWidth / scrollHeight` 一次性栅格化；因此页眉、页脚、水印与正文不会在两个导出器里各实现一遍。

**本模块 v0.24.0 的全部设计压在一条判据上：内容与装饰是两种寿命。** 内容渲染昂贵且只该发生一次（解析 Markdown、内联远端图、等字体与版面稳定）；装饰廉价却要在每一次拖动滑块时重来。两者原先焊在 `renderArticle(ctx, file, options)` 一个函数里，于是「实时预览」只能靠整篇重渲染——那是卡顿的另一个名字。拆成 paper（内容）与 decorate（装饰）之后，预览每帧只重放装饰，内容一帧都不重算。

**第二条判据：预览不是导出的仿真，预览就是导出物本身。** 纸默认停在离屏舞台上，预览只是把那个舞台挪进弹窗并按比例缩放；被 dom-to-image 拍下来的，始终是用户刚刚看着的同一个元素。若另画一份「示意图」，两者迟早走岔，而那时预览就在骗人——它给出的信心恰恰是最后才会被戳破的那种。截图前照终值再施一次装饰，则是为了堵住最后一道缝：用户拖完滑块立刻点导出时，预览排队中的那一帧可能还没轮到；`applyDecorations` 幂等，重放一次的代价是零。

**第三条判据管的是品牌标志（v0.24.0）：一个 logo，三处各自决定放多大。** 页眉、页脚与水印都能放它，但路径只有一个字段——你只有一个标志，让人在三处各选一遍同一张图不是灵活，是重复劳动。三处各有一个尺寸，**0 就是这一处不放**，与「文字留空即关闭」同一条语法，不必为标志再学一套开关。三个尺寸默认全 0，于是老库升级之后导出的那张图与升级前逐像素相同——新功能的默认值应当是「不发生」，而不是替他做了个决定。也因此，「这一段关不关」的判据从「文字为空」改成了**「文字与标志都没有」**：只放一枚标志不写字，正是落款最常见的样子。

风格落盘而不是只活在本次会话（`settings.exportStyle`），因为它的用途是**品牌**——品牌的定义就是每次都一样。只在用户点下「导出」之后才存：拖动途中的每一个中间值都不算数据，取消就该什么都没发生。

生命周期与异步交接：`paper` 在渲染完成、交出对象之前自行清理失败；成功后仍使用同一个幂等 `release`，先归还主题，再卸载组件，卸载异常也必须移除舞台。`exporter` 同时只允许一条导出流程持有纸张，避免两张纸互相覆盖全局主题的恢复快照；取消与失败都会释放入口。`modal` 关闭时撤销迟到选图与确认回调的写回权，保存框和最终交付共用点击当时的风格快照，防止等待期间切换格式导致扩展名与内容不一致。

纸张预设在 `panel` 边界把几何表的 `width/height` 明确映射为风格的 `pageWidth/pageHeight`，预览和截图均只读取后者；直接展开几何对象会只更新按钮状态，留下两份无效尺寸。旧设置没有段落开关时，`core/exportStyle` 从文字、标志与页眉页脚链接推导开关，只有网址的老页脚也保持可见；用户明确关闭的段落不重新推导。

## 成员清单

layout.ts: 无 DOM 的口径与几何层；模板占位符、文件名清洗、浏览器画布上限内的自适应倍率、PDF 单页 14,400pt 边界内的等比纸张，以及水印砖的尺寸、SVG 与落点。它刻意不量文字宽度——测宽要 canvas，canvas 一进来整层就不再可单测；宽度由装饰层量好递进来，于是「一行字斜过来占多大地方」仍是纯算术。
logoImport.ts: 「把电脑上的一张图搬进笔记库」那一步。它与 logo.ts 分成两个文件，判据与 appearance 把 snippets 与 reveal 分开时完全相同——**变更理由不同**：那边随 Obsidian 的读盘与画布走，这边随 Electron 走，而后者是红线上的一处缺口（备案第 12 条）。搬进库而不是记一条本机绝对路径：绝对路径换台电脑就断，还会把一条只在这台电脑上成立的绝对路径写进可同步的 data.json。落点固定在 `90-system/导出标志`——那棵树本来就被 isSystemPath 挡在全部检索之外，标志放进去不污染任何视图。同一张图重复挑不会堆出副本：按**字节**比对整个落点目录，因为用户第二次挑的多半是同一张图的另一个名字。
logo.ts: 标志层，回答一个很窄的问题——库里那条路径，变成能直接嵌进纸里的那串字节。它单独成文件的理由是**时序**：读盘是异步的，而装饰层必须全同步（预览每帧重放一次，那条链上一旦出现 await，帧与帧就会乱序）。于是解析被提前：路径变了才解一次，解出来的 ResolvedLogo 同步递给装饰层。它同时把图降采样到导出真正用得到的尺寸——一张 4000px 的原图编进 data URI 会让水印那一层的样式串膨胀到几 MB，而它最终只会被画成 80px 高；统一栅格化成 PNG 而不是「够小就原样透传」，是为了让标志只有一种字节形态，而那一种处处都画得出来。
paper.ts: 内容层，只回答「这篇笔记铺开来是什么样、有多大」。用官方 `MarkdownRenderer` 离屏重渲染全文（而不是截当前可见区），远端图片经 `requestUrl` 内联，等字体与连续三帧版面稳定。**它的版面口径全部量自用户此刻那个编辑区**：宽度、左右留白、字号、行高都抄自 `.markdown-preview-sizer`（阅读态）或 `.cm-content`（编辑态——**不是 `.cm-sizer`**，那是整个编辑器那一栏、左右内边距为 0，量它会让正文顶到纸边）——也正是 Obsidian 把「可读行宽」作用上去的那个元素。三个选择器按顺序找的是第一个**量得到**的，不是第一个存在的（v0.31.0 修）：一篇笔记只要被阅读视图渲过一次，那个 `.markdown-preview-sizer` 就一直留在 DOM 里，切回编辑态它不消失、只是宽度变 0——认「存在」就会在编辑态永远先撞上它，随即因宽度不合法整套回落 FALLBACK，于是**这条主线一次都没有真正跑过**，而它什么都不报：纸看上去有模有样，只是那三个数是写死的。v0.25.0 之前这层是三个常量（760 / 480 / 1600）加一句写死的 `padding: 48px 56px`，还会按 scrollWidth 把纸撑宽；**发明尺寸就是在替用户排版**，而那件事他已经在 Obsidian 的设置里回答过一次了。留白左右**取平均**合成一个数：编辑区那一栏的左右内边距本来就不对称，右边多出来的那截是留给滚动条的——屏幕上看不见，纸上没有滚动条就成了肉眼可见的偏心（真机量到左 88px、右 62px）。取平均而不是取大的那个，正文栏宽度因此分毫不变，改的只是它摆在哪儿。留白另有 48px 的下限——量到的元素未必自己带边距，而纸总得有边。v0.29.0 起还能指定导出的明暗（`setTheme()`），v0.31.0 起它**真的把界面切过去、用完再切回来**。原先只往舞台挂 `theme-light`/`theme-dark` 一个类，赌的是「主题把配色变量定义在不带 body 限定的选择器下」——这个赌注对**变量**基本成立，对**规则**不成立：凡是写成 `body.theme-dark .foo { … }` 的（Minimal 有、Style Settings 生成的有、这本库十三个片段也有），子树里挂多少个类都够不着那个 `body`，于是纸换了底色、Bases 表头与代码块却留着原来那身颜色。用户的判据是「把整个 Obsidian 想象成换了明暗主题再导出」——那就别想象，直接换：类挂到 Obsidian 自己挂的那个地方，每一条规则、每一个片段都按新主题重算，不存在够不着的死角。代价是界面会跟着变一下，而那恰恰是它的意思：预览就是导出物本身。换回来是无条件的——`release()` 的第一件事就是还债，导出失败、取消与 Esc 关窗都汇进 exporter 那个 finally。记的是「原来有没有这个类」而不是「原来是哪一套」：两个类都不在（跟随系统配色）时，后者会凭空加出一个。v0.27.0 起纸的两边各可钉死（`resize()`）：它只写两个 style 属性、一次 MarkdownRenderer 调用都没有，因为 Markdown 早已是 DOM，改容器宽度浏览器自己会重排——纸宽虽然改变版面，却与「解释一遍 Markdown」是两件事。高度那个值是**下限**不是定值：按定高裁内容就是静默截断，而缩放塞进去会改字号。不再因宽内容加宽是一次有意的取舍：超宽表格与代码行与它们在屏幕上的样子一致，留在自己那个横向滚动的盒子里。纸停靠时不再退到 `left:-100000px` 而是停在屏幕左上角、靠 `opacity:0` 隐藏：Bases 这类视图按「进没进视口」决定画不画单元格，停在十万像素之外时导出的表格有行却是空的。页边只由正文栏一处给出：纸自己的内边距一律清零（v0.31.0 修）——它挂着 `.markdown-preview-view`，主题会顺手再塞一份（真机 32px），留着它页边就有两个来源，而正文栏那份写死的宽度还会从这份内边距里整整溢出那么多，纸右边多出一条没有底色的带子；正文栏同版改成 `width: 100%` 跟着纸走，两处各记一份宽度时 `resize()` 漏改一处就溢出，且无声。`measure()` 的宽取纸**自己**的宽（`offsetWidth`）而不是含溢出的 `scrollWidth`——否则「不因宽内容加宽」那条决定只兑现了一半，纸不加宽、画布却加宽；高度反过来仍取 `scrollHeight`，纸本来就该跟着内容往下长。交出的 ExportPaper 同时管着「借给预览」与「收回离屏」两个动作——祖先带 transform 的元素不该被拍，这条纪律因此不散落在调用方手里。
decorate.ts: 装饰层，把一套风格施加到一张已经渲好的纸上，先清后建因此**幂等**，并且**全同步**。它另交出 `linkRegions`——页眉页脚那块可点区域在纸上的坐标，是本层唯一一样不是 DOM 的产物，理由是位置只有排完版才成立。链接参与「这一行有没有东西」的判断：只填链接不填文字时，链接原文就是这一行的内容（原本这种情况整行不存在、还不报错）。有链接时给那段字加下划线，**但只在 PDF 下加**——那条线的含义是「这里可以点」，而在 PNG 里那句话是假的。它同时收集正文里每一个外链的矩形（`getClientRects()` 逐行取，不是一个整包围盒——横跨两行的链接会把中间那段无关的空白也圈成可点）：那些链接是用户自己写进笔记里的，导出后全变成像素是不该由他承担的退化。页眉页脚那一块量的是那一行里**真正有墨的几段**（标志与文字各自的矩形）而不是整行的盒子：一行 flex 横跨整张纸宽，整块变成链接的话，用户点在标题右边八厘米的空白上也会跳转。标志的字节由 logo.ts 预先解析好递进来，本层一个 await 都没有（这条由回归读去掉注释后的源码钉住）。页眉页脚是一行 flex（图在左、字在右、整行按对齐落位），因此「靠左」说的是 justify-content；标志只钉高度、宽度随比例走，换一张更宽的标志时这一行的高度不跟着跳。水印平铺与单个共用同一张 SVG 底图，区别只在 `background-repeat` 与 `background-position`——两种排布若各写一套，改一处必然漏另一处。水印层的宽高按此刻真实的 `scrollWidth/scrollHeight` 写死而不是 `inset: 0`：纸的盒子高度与它的 scrollHeight 在内容溢出时并不相等，而截图取的正是后者。 v0.32.0 把可点区域收成一套算法：此前页眉页脚走 `offsetTop` 逐级累加、正文走客户端矩形，而 `offsetTop` 量的是「离最近那个**定位祖先**多远」——页眉页脚那一行只设了 `display:flex` 没有 `position`，于是子元素的 offsetTop 量的是离正文栏顶端多远，再加上行自己的 y 就把同一段距离算了两遍；页眉在 y≈0 算两遍还是 0（所以一直没人发现），页脚在 y≈1240 一加就落到纸外，真机 PDF 里 Rect 是负数、整条链接失效。修法不是给那一行补一个 position（那是让几何依赖一条为别的目的写下的 CSS），是让两处共用 `pushRects`。同版分出 `bodyLinkUrl`：正文的 href **不补协议**——「没写协议」在设置输入框里是「他省略了 https://」，在 DOM 里却是「这根本不是外链」，套错了会把 `[[MOC数据库代码]]` 变成 `https://moc数据库代码/`。
panel.ts: 右边那一列控件（v0.30.0 从 modal 分出来，判据与 settings/settingsPanels 同源：变更理由不同，触发点是那条 ≤800 行）。它要在三百二十像素里装下三十二个字段，靠的是两件事而不是把控件做小——**说明不常驻**（搬进名字的悬停提示，那一行灰字才是吃掉高度的大头）与**关着的段落不画**（三段各一个开关）；实测全关约 265px、全开约 820px，改版前是固定 2,400px。它刻意不 import obsidian，于是 docs/export-demo 能把同一列搬进浏览器跑；也刻意不用 Setting 原语——那是「名字在左、控件在右、说明在名字下面」的固定三件套，而这一列要的正是把第三件拿掉。
modal.ts: 唯一人机交互面的**骨架**：纸怎么缩放着摆进左边、状态怎么存、什么时候关窗、标志从哪儿来。标志有两条路各答一个问题——**从电脑选**是主路（用户的 logo 本来就在电脑上，逼他先拖进库是把实现细节当成他的工序），**从库里选**是次路也是手机上唯一那条。颜色栏比普通取色器多一枚「退回去」的按钮：取色器没有空态，而「跟随正文色」是一个有意义的状态，少了那枚按钮，点过一次就再也回不去。选标志走 core/modals 的 ChoiceModal 而不是让人手打路径——库里的图片是一个封闭集合，这条纪律与那个文件里写着的「凡取值来自封闭集合一律走 ChoiceModal」同源：手打出来的路径能通过一切非空校验，然后安静地渲不出图。谁该变灰由 EXPORT_SLIDERS 的 requires 字段决定而不是在这里逐根判断，因为那个判断一旦写错，用户会被锁在「要开标志得先拖那根滑块、而那根滑块正关着」里出不来。左边是缩放着的真纸，右边是控件；每一次改动只重放装饰、经 rAF 合帧。控件全部挂在 refreshers 一张表上，于是「恢复默认」不必逐个想起谁需要被同步——想不起来的那一个正是会出错的那一个。位置用位置来问：对齐是一排三枚互斥按钮，单个水印的落点是一张九宫格，而不是把空间压成一列文字的下拉框。平铺时那张九宫格整行收起而不是变灰——留着一个永远无效的控件，用户会以为是它坏了。
progressBody.ts: 导出进度那一块的**纯 DOM 半边**，零 obsidian 依赖——连 createDiv / setText / addClass 都不碰，因为那三个只在 Obsidian 里存在，而演示页要把它搬到浏览器里跑（第一版就栽在这儿）。按阶段推进而不按字节：dom-to-image 不给回调，字节级百分比只能靠编。step() 等**两**帧才放行，否则紧接着那段同步重活会把更新压住，条从头到尾只画一次。
progress.ts: 上面那半边的 Obsidian 宿主，只管开窗、关窗、改标题、成功后退场。它替换的是一条右上角的 Notice——一条不会动的提示无法区分「在做」与「卡住」，那正是「盲盒感」的来源。
exporter.ts: 编排与运行时边界，只讲流程：渲一张纸 → 交给预览 → **先问去处** → 照终值再施一次风格 → 一次性截图 → 写进那个去处。先问后做是 v0.26.0 纠正的顺序：旧流程点完导出先关窗、再栅格化好几秒、保存框最后才来，而那几秒完全可能白花。`chooseTarget` 把去处问成一个值，预览弹窗拿一个 confirm 回调，取消保存框就把弹窗留在原地。桌面优先借 Electron 保存对话框，探不到则与移动端一起回落到笔记库附件位置。

## 依赖方向

`exporter → {paper, decorate, modal} → layout → core/exportStyle`。paper 与 decorate 彼此不认识：一个只认内容，一个只认风格，两者唯一的交汇是那个被传来传去的 `article` 元素。modal 不认识 paper 怎么渲出来的（它只拿到一个已经渲好的 ExportPaper），因此它永远没有机会在预览里重新解释一遍 Markdown——那条边界由 tests/export.mjs 明文钉住。

持久化契约 `ExportStyle` 住在 `core/exportStyle` 而不是本目录，理由与 markdownStyle / device 完全相同：`normalizeSettings` 要验它的形，而 core 不能反向 import 一个功能模块，否则依赖图从一棵树变成一张网。那份契约里的 `EXPORT_SLIDERS` 同时是界面的滑块范围与持久化的验形区间——一份事实两处使用，因此「界面能拖到的值」与「重启后还认的值」不可能对不上。
