# modules/appearance/

> L2 | 父级: ../../CLAUDE.md

外观模块。它是全库唯一不生产笔记的功能模块——不建目录、不写 Markdown、不报 VaultSeed，因此在开荒流程里完全缺席。它管的是另一件事：库里那十三个 CSS 片段，此刻哪些开着、怎么在不进设置页的前提下改这件事，以及 v0.20.0 起补上的后半句——**怎么去改片段本身**。第十三个「突出废弃内容」在 v0.22.10 把 Markdown 删除线从一条几乎看不出的默认细线收成系统语义：编辑/阅读两态同时弱化正文、铺淡警示色背景并画 2px 警示色线，不靠颜色一个信号，也不用伪元素插入「已废弃」去打断原句。v0.22.12 再把其中的双链从普通旧文字里提出来：解析正常也用橙色风险底、红色划线与边界提醒“入口可能过期”，已解析不到目标的链接则显示红色双边界，区分风险与既成断链。

前半句与后半句的分界值得记一笔：开关回答「要不要」，此前没有任何东西回答「怎么改」。从「在面板里看见这个片段」到「改到这个片段」之间，用户要退出面板、找到笔记库文件夹、打开被系统默认隐藏的 `.obsidian`、进 `snippets`、在十三个中文文件名里认出刚才那一个。两个出境口（每行开关左边一个、页脚右下角一个）补的就是这段路。

它存在的理由是一个具体的坑：社区插件 MySnippets 曾经做过这件事，但它把开关塞进 Obsidian 的 `Menu` 内部 DOM、用写死的像素偏移定位、并依赖一个随 Obsidian 换图标库而消失的图标名，于是在新版本里散成了一个看不见也点不动的按钮。这里三条都反着来：浮层是自己的 div，位置由按钮的实际矩形算出，图标画完当场检查画出来没有。

## 成员清单

snippets.ts: 事实层与动作层（对 Obsidian 的 CSS 子系统而言），也是全仓库两处接触 Obsidian 非公开 API 的**第一处**（v0.17.0 起另有 modules/legacy 那三处，同一套三条纪律收窄）。事实全部走公开 API——片段清单来自 `vault.configDir` + `DataAdapter.list`，启用清单来自 `appearance.json`，因此开关里看到的与「设置 → 外观」看到的永远是同一份，不依赖任何内部实现。这个配置不只属于插件：文件存在却读不懂或顶层不是对象时必须拒绝开关，绝不能拿空对象覆盖用户的主题、强调色与其他外观设置（v0.16.0 审计补入）。只有「让改动此刻生效」没有公开替代品：`obsidian.d.ts` 全文既无 `customCss` 也无 `snippet`，唯一能做到的是 `app.customCss.setCssEnabledStatus`。它被模块增强声明成**可选**成员并在运行时二次验形，于是内部实现哪天变了，后果被锁死在「退回改配置文件 + 提示重载」，而不是在用户库里抛异常。筛片段的后缀判据与 Obsidian 一致取小写 `.css`——放宽成大小写不敏感，开关里就会出现一条 Obsidian 根本没加载、点了也没反应的片段。
reveal.ts: 出境口，也是全仓库第二处直接向 Electron 伸手的地方（第一处是 books/sourceWeread 的扫码登录窗口，同一套三条纪律收窄，备案第 10 条）。它单独成文件而不是并进 snippets.ts，判据是**变更理由不同**：那个文件会因为 Obsidian 的 CSS 子系统变而变，这个文件只会因为 Electron 变而变，两个外部依赖挤在一起，将来任何一处塌方都要把另一处一起翻出来读。借来的只有「打开」这最后一步——绝对路径走公开的 `FileSystemAdapter.getBasePath()`（obsidian.d.ts 里标着 @public 的导出类），所以「文件在哪」全程由 Obsidian 回答，塌方时坏掉的是两个按钮而不是路径、清单与开关。那段计算 v0.21.0 搬进了 `core/localPath`（状态栏那块路径成了第二个调用方），本文件只留「拿不到就翻成一句中文抛出去」这一句反应：算路径与 Electron 无关，留在这儿会让上面「只因 Electron 而变」那句话名不副实。它把「能不能」拆成两问：`canReveal` 只答稳定且公开的那半个（是不是桌面端、库在不在本机文件系统上），Electron 探得到探不到留到**点下去的那一刻**才验——注册发生在插件加载最早的一段，热重载与版本升级都可能让答案在之后改变。`openSnippetFile` 返回布尔而不抛异常，与 setSnippetEnabled 用「即刻生效 / 只落了盘」区分两种成功是同一套写法：默认程序接手了就闭嘴，没登记 .css 默认程序则退一步在文件管理器里选中它并说一声。打开片段目录时目录不存在就先建——这个按钮最该有用的时刻恰恰是「库里还一个片段都没有、我想去放一个进去」。
statusBar.ts: 呈现层，右下角状态栏按钮与它弹出的浮层。它只认识 snippets.ts 给出的四个字段（name/group/label/enabled），不认识 Obsidian 的 CSS 子系统。分组直接读用户文件名开头的【】前缀，不另发明一套分类：命名习惯是用户的，我们只是照着显示。每次打开现读一次磁盘，因此用户在设置页里的改动、或刚丢进目录的新文件，下一次打开就都在——无缓存、无监听、无轮询。两个出境口的长相不同是有判据的：行内那个只有图标（它一屏出现十三次，十三个「打开这个 CSS 文件」会把片段名挤走，而它在哪一行本身就说明了它开哪个文件），页脚那个带文字（每面板只出现一次，说清去哪儿的成本只付一遍）。行内按钮排在开关**之前**，因为 ToggleComponent 是往行上追加的——谁先建谁在左边，位置本身是句话：先问怎么改，再问要不要。页脚是 sticky 而非普通块，这是必须而非讲究：浮层有 460px 高度上限，十三个片段一定滚动，页脚随内容走就把「右下角那个按钮」变成了「滚到底才看得见的按钮」。两个按钮都只在 canReveal 为真时画出来（手机上没有文件管理器可去），且点完不关面板——想改 CSS 的人往往一次要开好几个对照着看。

## 与外部的接线

对上只暴露一个装配入口 `registerAppearanceSwitch(ctx)`，它返回一个「按当前设置重新决定按钮显隐」的同步函数。设置页只会改设置对象并落盘，无从知道屏幕上已经画着一个按钮，所以这个函数由 main 转交过去——与「记人情要日记」「客户要开荒」「侧边栏要重新显隐」用的是同一套填洞手法，依赖图仍是一棵树。

打开这个面板现在有三条路：右下角那个按钮、命令面板里的「打开外观开关」、以及左侧边栏那个调色盘图标（勾选默认开着）。三条路指向同一个 toggle，因为它们注册的是同一条命令——本模块经 ctx.commands 注册，边栏是照花名册摆的。

片段文件本身不归本模块所有：它们是 `vault/.obsidian/snippets/` 里的交付物，由安装契约铺下去，插件只负责开关与把它们交到用户的编辑器手上。因此删掉这个模块，库里的外观一个像素都不会变，只是少了那个按钮——同时红线上那两处缺口（Obsidian 非公开成员的第一处、Electron 的第二处）也一并消失。
