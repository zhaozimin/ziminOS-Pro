# src/modules/setup/

> L2 | 父级: ../../CLAUDE.md

开荒模块。它在 V2 从 projects 里独立出来，因为开荒横跨全库骨架并要收齐三个模块的诉求——住在其中任何一个模块下面，都是让物理位置对读者说谎。

## 成员清单

init.ts: 开荒编排，由设置页按钮与 init-vault 命令唯一触发。它只保证两件事属于笔记库本身：PARA 骨架目录，以及「开荒过没有」这个事实。其余产物一律由各功能模块自报 VaultSeed，main 装配后递进来——因此本文件不 import 任何兄弟模块，加一个模块只需在 main 多传一个 seed，这里一行不改。另导出 applySeed 供客户模块的按需开荒复用，让「开荒时长出」与「按需长出」是同一段代码的两个触发点，而不是两份各自演化的实现。开荒收尾把学员送到 README 而非导航（v0.10.1）：README 头部是作者名片、正文是说明书，刚开完荒的人需要的是说明书；日常入口仍是导航。只拿到 main.js 的库没有 README，回落导航。

schemaNote.ts: 属性类型示例笔记的纯文本工厂，与 `.obsidian/types.json` 共同组成属性契约的机器相与人类可读相；示例刻意使用视图不认识的 type，避免它污染任何业务名录。

## 模块契约

首次开荒与后续补齐走同一条流程，差别只有三处：空库检查、各模块的 finish、以及 initializedAt 只在首次确定性种子落齐后写一次。首次检查会排除已生成的种子路径，initializedAt 又在可选 finish 之前提交，因此中途失败不会让插件自己的半成品反过来封死恢复入口。补齐时重写首次时间等于让面板向学员陈述一件关于他笔记库历史的假事，故严格禁止。

VaultSeed 是本模块认识的唯一形态。它有三个字段而不是两个——folders 与 notes 之外还有可选的 finish，因为「开出第一个项目」这类动作只该在首次发生，而它天然属于提出诉求的那个模块，不属于开荒本身。

第七个根文件夹 05-diary 不在 INIT_FOLDERS 里，人脉目录也不在。它们由复盘与人脉模块各自带来：「这个目录存在，是因为那个模块存在」这件事必须在代码里也成立，否则删掉一个模块，库里会留下一个永远空着的目录。
