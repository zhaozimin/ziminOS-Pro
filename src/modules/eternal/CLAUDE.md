# src/modules/eternal/

> L2 | 父级: ../../CLAUDE.md

赛博永生模块，第二版（付费·三库）专属。它是全仓库唯一一个**默认不注册**的模块：main 只在版次标记判定为 pro、且本库角色对得上时才接它的线，免费版里它的任何一行代码都不会被执行。这条纪律不是配置开关而是装配期开关——没有命令、没有视图、没有监听，也就没有任何东西可能在第一版用户的库里出错。

它解决的是一个被红线挤出来的问题：项目归档时要把副本送进隔壁那本库，而 Obsidian 的 vault API 被沙箱锁在本库内。借 Node fs 能做到，但那会是「只用官方公开 API」的第三处缺口，且手机上必炸。于是本模块**只记意图、不搬文件**：插件往本库的一篇 Markdown 上追加一行「欠了这一笔」，真正的跨库拷贝与提炼交给桌面智能体。分工的判据不是将就——提炼本来就只有智能体干得了，让它一次进门把搬运与提炼一起做完，比让文件先躺过去等着更顺。

## 成员清单

manifest.ts: 出库单的纯文本层，不认识磁盘也不认识 Obsidian。渲染与解析紧挨着写，因为它们是同一份格式的两面：插件按 manifestLine 写、按 parseManifestLine 读，智能体按同一份格式勾选，三方共用而格式只存在一处。行的形态是标准 Markdown 任务行而非自造格式——这本库里「还没做的事」长什么样已经有答案了，再发明一种只会让学员多学一样东西，而任务行天然可勾、可搜、可手改。解析刻意宽容、渲染刻意严格：它从行的两端与固定包装定位字段，项目名和路径里的可见分隔符不再把 UID 推错位；清单是用户可以随手编辑的，改乱的行只该让那一行落选，不该让整个视图炸掉。唯一的硬判据是必须找得到 UID——没有它的行在《赛博永生》里对不上号，重复归档还会长出第二页讲同一件事的 wiki。
export.ts: 写入侧，也是第二版唯一一处跨库意图的落点（落的是意图不是文件）。它对失败的姿态由归档本身决定：归档已经落地了，出库单写不成只意味着少记一笔待办，因此全程不向上抛错，只报一句话。三种情况静默跳过：本库不是「以人为本」、同一个 UID 已经在单子上、拿不到 UID（这一种要提示，因为用户会想知道为什么这个项目没被送过去）。同一 UID 不重复追加，是因为项目可以被重新开始再次完成——智能体按 UID 认出那是同一件事的新版本，插件这边只需保证单子上不出现两行。
views.ts: 读取侧，两张清单住在两本不同的库里，回答同一条流水线上前后两道工序的问题：「以人为本」那张问「还有什么没送出去」，《赛博永生》那张问「送进来的还有什么没消化」。刻意不合并，因为插件看不见隔壁库，一张跨库的清单只能靠猜，而猜出来的数字会让人以为活儿干完了。「待提炼」判定已消化与否读的是账本而不是原料上的标记——原料层是卡帕西那三层里的 Raw，往里写一个 ingested 字段它就不再是当初归档时的那份东西了；账本在外面记，原料保持原样。账本的解析判据宽松也是安全侧：格式要求越严，越容易在某次手改后整体失效，而失效的表现是所有原料忽然都变成待提炼，接着一次重复提炼就把 wiki 写乱了。同一条判据决定了消化标记读中文的「消化」也读旧的英文 `ingest`——账本是智能体逐行追加、用户也会手改的文件，某台机器上的契约副本可能还没更新，少认一个标记不报错，只会静静地重复消化一遍。「待提炼」那张表的类型列也走 KIND_LABELS：原料是原样拷来的项目 MOC，它的 type 是 project/book 这种机器值，而这本库里用户看得见的每一个词都是中文，单让这一列说英文等于在一张中文表里留一个没人解释的字段。

## 模块契约

出库单的判重与追加必须在同一次 `vault.process` 中读取最新正文，不能把较早的整篇快照交给 `modify`。并发归档的每个 UID 与用户同时写下的备注都要保留；首次创建遇到另一条写入先建成时复用其 `TFile`，文件夹占位仍报错。成功提示只在原子回调确实新增一行后发出，重复 UID 保持安静。

对外只暴露三样：`createExportHook`（造出归档移交的接收函数）、`humanEternalViews` 与 `eternalRawViews`。归档这件事本身归 projects 模块，本模块不认识它——`ArchivedContainer` / `ArchivedHook` 两个契约住在 core/types，与 VaultSeed 同一个理由：它是两个模块之间的约定，放在任何一侧都会让依赖图从树变成网。

出库单的路径、小节标题与字段分隔符全部收在 core/constants，判据与 DIARY_LOG_HEADING 完全相同——它们是**写入方与读取方共同的约定**，而读取方这次多了一个不在本仓库里的角色（桌面智能体）。分隔符取「 · 」而不是人情账本那个全角竖线，是因为两种行长得像，解析器迟早会把一个已归档项目当成一笔人情债记进别人的档案，且不报错。
