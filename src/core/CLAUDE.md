# src/core/

> L2 | 父级: ../CLAUDE.md

基础设施层。判断一个文件该不该住在这里只有一条标准：它是否谈论「项目」「卡片」「归档」「人脉」这类业务概念——谈了就属于 modules，不谈才留在 core。V2 兑现了这句话：人脉与复盘两个模块加进来时，core 只是长出了三个同样不懂业务的新文件（事实层、呈现层、宿主），原有七个文件的语义一个字没改。外观包属于 vault 交付物，不依赖插件 core。

## 成员清单

constants.ts: 全仓库业务字典，零 import，是依赖图最底层的叶子。目录/字段/日期/项目状态/复盘/人脉/读书/外观/文件浏览器/光标/视图等跨模块约定在此；两张内建总控台固定为 `MOC-人脉.md` 与 `MOC-客户.md`，初始化路径、人物归属双链和打开入口只能从这两个常量推导，旧名常量只供已安装库兼容寻址，不得用于新建。只随本机设备交互变化的参数分给 device.ts，命令身份与宿主 DOM 约定仍留在各自边界。
device.ts: 本机设备契约叶子，零 import。收口状态栏复制口径及 Eagle 端口/默认文件夹 ID，让设置验形、设置界面与协议客户端依赖同一份参数，不让全局业务字典继续承担设备配置的变更理由。
commands.ts: 命令这件事的全部——三十八条命令的身份（id / 中文名 / 图标名 / 分组）、十一个分组的功能色 GROUP_COLORS、左侧边栏的默认摆件清单，以及注册台 CommandRegistry。COMMAND_ICONS 有四十一个名字而命令只有三十八条：多出的 dock / explorer / editing 服务设置页那三张没有命令与之对应的标签页——它们管的都是屏幕上的一块地方而不是一件可执行的事，但图标仍归这张表，因为设置页的标签与边栏图标必须同源。「打开中国日历」「升级存量 MOC 数据库」「补齐客户答疑检索」与「导出当前笔记」都不加入默认十枚边栏按钮：前三者已有固定入口或只需一次，导出则是低频交付动作。注册台同时把命令交给 Obsidian 并留在花名册；花名册存回调本体，边栏不必依赖未公开的 executeCommandById。注册顺序即花名册顺序，也就是边栏的初始顺序。
edition.ts: 版次闸门，「同一份 main.js 交付两版用户」这条纪律的唯一执行处。第一版（免费·单库）与第二版（付费·三库）共用同一个插件产物，所以「这个库能用哪些功能」不能写死在代码里，只能问磁盘上一份由第二版安装器写下、第一版永远没有的标记文件。它给出的不是运行时开关而是**装配期开关**：main 拿到 free 就根本不接第二版那条线，没有命令、没有视图、没有监听，也就没有任何东西可能在免费用户的库里出错。失败方向是刻意的——文件缺席、读不动、JSON 坏了、字段不认识，一律回落 free；坏标记把付费功能塞进免费库，比坏标记让付费库退化成免费库严重得多，因为后者用户看得见（功能不见了会来问），前者他看不见（凭空多出的文件不会有人报错）。它同时是三库布局的唯一事实源，插件与桌面智能体读同一份 vaults 表，因此「赛博永生那本库叫什么」不存在两个答案；从第一版升级上来的用户那本库叫什么是他自己取的，这也是布局必须是数据而不能是常量的原因。
types.ts: 契约层。ZiminosSettings 与 DEFAULT_SETTINGS 定义可持久化选择，normalizeSettings 是未知 JSON 的唯一验形边界；v0.22.0 加入 `eagleEnabled/eaglePort/eagleFolderId`，新字段按默认值补给老库，端口严格收口到合法整数；v0.22.4 把 `eagleFolderId` 收窄为项目外附件的兜底；v0.22.5 增加默认关闭的 `eagleExcludeImages`，只在用户明确选择时将纯图片事件放行给图床。**认证令牌不属于设置**，刻意没有字段：它是设备秘密，交给 Obsidian 官方 `SecretStorage`，绝不能随 data.json 同步或被安装器读取。
exportStyle.ts: 导出风格的口径层，零 import，与 markdownStyle / device 同列——模块自己的设置形状必须住在 core，否则 normalizeSettings 就得反向 import 一个功能模块。它定义格式、页眉页脚对齐、水印排布与九宫格四个闭合集合，以及三十二个字段的 ExportStyle 与它的验形——其中品牌标志只有一条路径，三处（页眉/页脚/水印）各有一个尺寸，0 即那一处不放，三者默认全 0 以保证老库升级后导出逐像素不变。最要紧的设计是 EXPORT_SLIDERS：它**同时**是弹窗里那七根滑块的取值范围与持久化的夹取区间，一份事实两处使用，因此「界面能拖到的值」与「重启后还认的值」不可能对不上；越界的数字夹回区间而不是回落默认（手改过 data.json 的人想要的是「尽量大」，读成默认会让他以为没保存），不是数字才回落——那时没有意图可言。颜色只认十六进制色号、坏值一律回落空串（＝跟随正文色）：这个值会被直接写进 SVG 的 fill 与元素的 style，放任意字符串进来，一条 `red; content: url(…)` 就成了一次样式注入。三个段落开关（页眉/页脚/水印）把「关闭」从推断变成声明，**键不存在时从内容推导**——取 false 会让升级上来的人页眉页脚水印一夜消失，取 true 会让空段落平白展开。导出明暗（跟随/亮色/暗色）与 Obsidian 当前主题分开，默认跟随——换了默认，所有人下一次导出的底色都变了。纸张两边各有一个自适应/自定开关：高度那个的语义是**至少**而不是**就是**，因为按定高裁内容就是静默截断。滑块的键由 ExportStyle 的数字字段推导而来，加一个数字字段却忘了给它滑块，编译器当场就会指出来。每根滑块另带一个 requires（text / logo / mark / switch），回答「它得先有什么才谈得上有意义」——界面照它决定谁该变灰；没有这个字段，「文字一空就把标志大小也一起禁掉」会让用户永远打不开标志，因为要开标志得先拖那根正被关着的滑块。
time.ts: 时间口径统一处，也是 dateTimeFormat 的守门人。periodOfTitle 是 currentPeriodTitle 的逆函数——由文件名反解出它是哪一级周期笔记，五种标题格式在严格解析下互不相容，因此结果唯一且与遍历次序无关；全仓库只有这一处回答「这个文件名是哪一级」。原始脚本的手写时间统一收敛为 moment；nowStampAndUid 保证 created/UID 同源，nowLocalDateTimeParts 保证灵感模板的 date/time/datetime 在同一时刻生成。dayText 只接受真实存在的 ISO 日期，不让 `2026-02-29` 这类伪日期进入区间视图。调用方不自行 new Date 拼时间，避免跨秒或跨分钟分叉。
localPath.ts: 「Obsidian 眼里的相对路径，在操作系统眼里叫什么」的唯一答案。外观片段、状态栏复制与 Eagle 伴侣安装包三个调用方共用；返回可空而不抛，按 macOS/Windows 生成本机分隔符，事实层不替调用方决定失败话术。
folders.ts: 目录保障。ensureFolderPath 逐级创建并在同名文件挡路时抛出明确错误；normalizeFolderPath 把用户在设置页敲进去的自由文本收敛成可用路径，空值回落默认——校验集中在读取侧，是设置页敢于不做校验的前提。isSystemPath 是「功能目录不参与检索」这条纪律的唯一判定处：90-system 里住的是导航、模板与属性示例，是系统的零件而非知识，视图引擎与两处直扫共用这一个函数排除它。
frontmatter.ts: YAML 字段判定与重排。hasValue / isCardInitialized / reorderFrontmatter 决定「一篇笔记算不算已登记的卡片」；isMocFrontmatter 是规格授权的一处刻意偏离，把 MOC 判据从 type ∈ {project, area} 放宽为 type 有值，否则 type: book 的 MOC 会被误当卡片改写。
modals.ts: 唯一人机问答通道。把弹窗生命周期翻译成 Promise：有输入返回文本，取消返回 null，调用方因此能用一条 if 中止流程。三个弹窗的分工是纪律而非口味——凡取值来自封闭集合（分层、方向、去/来、状态、产品、渠道、选人、选一本书）一律走 ChoiceModal；TextAreaModal 与 TextInputModal 分成两个类而不是一个开关，是因为两者的回车语义相反：单行里回车即提交，多行里回车是换行（粘贴进来的划线自己就带换行），提交改由 Cmd/Ctrl+Enter 与确认按钮承担。实测证据是硬的：用自由文本问「今天做了什么」，34 篇日记收到 34 个「123123」类垃圾，而垃圾能通过一切非空校验并作为事实进入汇总表。枚举让垃圾在语法上不可能产生，这比任何校验都可靠。
vaultIndex.ts: 视图引擎的事实层，全部数据视图的唯一数据来源（二十四个视图里只有「关于作者」不读它——那张名片是编译期常量）。V4 起它在两张入口上排除功能目录：allNotes 过滤 90-system、反向链接表跳过 90-system 源——属性示例里的「[[某位客户]]」是教材不是事实，排除做在事实层，二十四个视图自动继承。它只回答关于文件的客观问题——谁链到了我、这个链接指向哪个文件、这篇笔记有哪些列表行，以及某个 frontmatter 链接是否真的解析到目标。客户答疑正是最后一条的第一个调用方：正文顺手提到 Alex 不算，只有任一属性值里的双链才算归档到 Alex。链接一律经 getFirstLinkpathDest 解析成文件再比对，别名、子路径、锚点三种写法都认得；懒构建 + 修订号自校验取代 Dataview 轮询，两次渲染之间没有任何后台活动。反向链接表一次遍历建成、同一渲染周期共用，把「人数 × 全库」降成「全库」。
table.ts: 视图引擎的呈现层，只认识「表头 + 行 + 单元格」与「一组任务」。三条纪律都来自与原版 Dataview 的真机对比：其一，文本里的 `[[双链]]` 必须渲染成可点的链接——视图检索出来的是日记原文，原文里的人名与项目名都是双链，渲染成死文本等于把一张关系网拍平成一段字符串；其二，任务行渲染成真的复选框并能勾，勾选写回源文件那一行，因为看起来像复选框却点不动是撒谎；待办本身也走同一个 renderTable 画成三线表（事项一列、日期一列），复选框与事项同处一格——待办不该是这套系统里唯一长得不一样的东西，而勾选框离它要勾的那句话越远越容易勾错。其三，表格是三线表并占满整行，且由调用方指出哪一列是句子列去吃掉余量：不指定的话浏览器按内容比例摊给每一列，结果是每列都窄一点、每列都要换行；逻辑上同一张表还必须一次画完（两次建表会得到两个各自算列宽的 table，列必然错位）。它只认双链一种标记而不接完整 Markdown 渲染器：那些文本是用户日记里的原话，交给渲染器等于把用户数据当代码执行。空态有专门的原语且强制带一句下一步指引，而那句指引里的示例必须走行内代码：空态正文教的就是「照着这行抄」，把包着示例的反引号原样打印出来，学员会连反引号一起抄进日记，那一行从此不再被解析成账——教语法的句子自己必须先把语法显示对。因此 renderRichText 认 `**加粗**` 与 `` `行内代码` `` 两种标记，一遍扫描先到先得，落单的星号或反引号原样留着。样式在插件自带的 styles.css 里，全部选择器带 ziminos- 前缀、颜色取 Obsidian 语义变量，因此跟随主题与配色走。表格撑满整行靠的是改写主题变量，而不是自己声明宽度：Minimal 用一条打头六个类的选择器（特异性 (0,6,1)）把 table 的 width / min-width / max-width 三条一起接管，取值全来自 `--table-*` 变量，默认 `--table-width: auto` 就是「按内容收缩」，`--table-min-width` 甚至没有定义。我们那条 `div.ziminos-table-wrap > table.ziminos-table` 只有 (0,2,2)，三条都压不住——曾经以为「min-width 不参与竞争」是误判，主题连它一起设了。出路不是堆特异性也不是 !important：那条规则是主题的实现，变量才是主题的接口，于是在包裹层上把四个变量改写成 100%，主题自己算出来的就是整行宽。不认识这些变量的主题走 styles.css 里那条同向的 100% 兜底，两条路结果一致。这也是全库表格宽度视觉一致的唯一来源——按内容收缩时，同一页两张表必然宽窄不一。
codeblock.ts: 视图引擎的宿主，把「学员写下的一个代码块」翻译成「一次视图渲染」，并管住这次渲染的全部生命周期。它不认识任何具体视图，清单由 main 装配时递进来。重算策略是它最关键的设计：变更事件只递增修订号并排一次防抖，到点后由宿主统一重算全部在场的块——既不轮询，也不会出现「块比索引先醒来、拿着上一版数据重画一遍」的竞态，因为失效与重算由同一个入口先后执行，顺序不依赖事件注册的先后。
markdownStyle.ts: Markdown 排版层，零 import，与 markdown.ts 分工明确——那边动的是「往哪一行插什么」，这边动的是「这一篇写得规不规范」。九条标准写法（中英空格、标题/列表/表格/代码块上下留空行、YAML 后留空行、连续空行收一行、去行尾空格、文末一个换行）合成一趟纯函数变换，同输入同输出且**幂等**：幂等不是碰巧成立的性质而是设计前提，自动整理正是靠「第二趟算出来的与第一趟一字不差」断开「写盘 → 触发监听 → 再写盘」这个环。它最要紧的不是加空格而是**不加**：文件名、双链、行内代码、URL、标签、YAML 整段保护，`[[MOC-人脉]]` 里插一个空格就断链，而断链既不报错也没人当天发现；但保护段**外面**照加——空格落在方括号之外、链接一字未动，这个区分是整条规则的要害。九条规则的开关由调用方递进来，全关时它是恒等函数。
markdownViewState.ts: Markdown 后台写入的视图稳定层。`Vault.process` 与 `processFrontMatter` 能保证磁盘内容不被并发覆盖，但写入回推到已打开的非活动分栏时，Obsidian 可能重建视图并把滚动条放回文首。本文件用公开的 `iterateAllLeaves` + `MarkdownView.currentMode` 在写前捕获同一路径的所有已加载分栏，写后立即与下一帧各恢复一次。已换文件或切模式的视图不恢复，新选择永远优先于旧状态；延迟页签按官方要求用 `instanceof` 过滤。它只管屏幕位置，不介入任何业务写入。
markdown.ts: 纯文本操作层，两件事。其一，往既有笔记的某个小节里追加一行记录（记人情写进日记、增加付费写进客户档案、记收款写进项目 MOC）——三个落点规则完全一样，所以规则只存在一份。其二，翻转某一行的复选框：写之前先比对那一行还是不是预期的那条任务，对不上就返回 null 让调用方什么都不做——视图渲染之后用户可能改过源文件，行号会漂，而勾错一条别人的待办比没勾上难发现得多。三条行为都是为了让插进去的那一行看起来像人自己写的：插在视图代码块之前（数据在上、汇总在下）、用掉模板留下的空占位行、找不到小节时宁可追加到文末也绝不拒绝写入——学员改过标题不该导致他的记录丢失。
guard.ts: 自激循环断路器。插件的自动化监听 vault 事件，而插件自己的写盘同样触发这些事件——所有写路径动手前 mark，所有监听动手前问 isRecent，两端配合把「机器的动作」与「人的动作」区分开。isRecent 遍历时顺手清过期项，不另起定时器，守住「无后台轮询」红线。

## 审计后边界

`codeblock.ts` 的异步渲染先落在离屏容器，只有最新代且仍在场的实例能一次性提交 DOM；旧请求晚返回、或代码块已经卸载，都没有权覆盖新视图。`markdownStyle.ts` 内部统一用 LF 扫描，但出口恢复输入原有的 CRLF / CR / LF 约定，排版不再制造整篇伪差异。

## 内部依赖

constants 与 device 都零依赖，是依赖图最底层的叶子；commands 只向下够到 constants（借 PeriodKey 与 TransitionAction 两个类型），因此自己也几乎是叶子。edition 只依赖 obsidian 的 App 类型，同样是叶子。localPath 只依赖 obsidian（一个类、一个平台标志与一个类型），因此也几乎是叶子。绝大多数文件只依赖 constants/device 与 obsidian；横向依赖仍只有三条，都指向更底层：types 引用 guard、commands、markdownStyle 与 edition（各取一份默认值或类型），codeblock 引用 vaultIndex、table 与 types。markdownStyle 与 exportStyle 都与 constants 一样零 import，因此它们被 types 依赖同样不会成环。方向始终由「懂得多的」指向「懂得少的」，故 core 内部无环——commands 之所以能被 types 依赖而不成环，正是因为它自己只够到 constants。
