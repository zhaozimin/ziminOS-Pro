# 口述捕获

执行一律调用 `notectl.py`（安装后在 `系统根/.ziminos/skills/scripts/notectl.py`）。**禁止手写文件、禁止用 Edit 直接改笔记、禁止管道灌 JSON、禁止 heredoc。** 内容含引号或换行时用 `--content-file <绝对路径>`。

理由不是规矩多：目标路径、清洗、链接搬运、人名双链、插入位置、日记骨架，全都是同输入同结果的活儿，脚本每次算出来的一样，你每次可能不一样。而这套系统对用户最硬的承诺是**原话保留**。

---

## 1. 四分判据

| 用户在说 | 归哪一类 | 命令 |
| --- | --- | --- |
| 一个想法、判断、点子；「灵感：」「记一下这个想法」「突然想到」 | 灵感 | `inspiration` |
| 一条链接、一句带链接的话 | 灵感 | `inspiration` |
| 转发来的一整段内容、一篇文章正文 | 剪藏 | `clip` |
| 今天发生的事、见了谁、聊了什么；「记一下今天」「写进日记」 | 日记 | `diary` |
| 读书划线、概念笔记、整理知识体系 | **都不是** | 不写。如实说明口述只接住原话，整理仍在 Obsidian 里做 |

**灵感与剪藏的分界是体量，不是内容**：一句话进流水，一整段进单独的文件。判据是下游——剪藏日后可能被《赛博永生》逐条消化，而流水里的一行没法单独标记「这条消化过了」。拿不准就按灵感记，一句话的东西不值得单开一页。

**灵感与日记分不清时看时间指向**：指向未来或指向某个判断的是灵感，指向今天已发生的是日记。判错的代价很小（进错库，用户一眼看得见、随手能改），所以**不要为此反问**。

「灵感：」这类前缀不是必需的咒语，有则百分百确定，没有就按语义判断。**绝不要求用户学固定说法。**

## 2. 写入

```bash
python3 ~/…/.ziminos/skills/scripts/notectl.py inspiration --content "定价页把年付放在最前面"
python3 ~/…/.ziminos/skills/scripts/notectl.py diary --content "下午和王磊过了一遍课程大纲"
python3 ~/…/.ziminos/skills/scripts/notectl.py clip --title "分层架构那篇" --content-file /tmp/x.md
```

先跑一次 `status` 确认三本库都在，再写。`status` 报错就照实说明，不要试图自己找库。

### 今天的日记还没建时

`diary` 会回 `theme_required`（退出码 2）。此时**问用户一句「今天的主题是什么」**，拿到回答再重发：

```bash
… diary --content "下午和王磊过了一遍课程大纲" --theme "课程结构定稿"
```

主题是他对这一天的结论，**不许你替他想，也不许从他刚说的那句话里提炼**。他说不想写，就传 `--theme ""`，日记照建、主题留空。日记建好后当天后续的记录不会再问——**这是整套捕获里唯一允许为了写入而反问的地方。**

### 带链接的时候

**原样把地址塞进 `--content` 就行，不要自己排版。** 脚本会决定它是搬到下一行的子项还是就地包成 Markdown 链接。

**不要替他改写链接文字，不要去访问那个地址取标题。** 取标题要出网，而这套系统对用户的承诺是记录的过程不联网。

### 原话保留是红线

不润色、不总结、不改措辞、不替他补主语、不加标签。脚本只做两件清洗：压缩空白，以及把全角竖线换成半角（它会被《以人为本》误解析成人情账本，在别人的档案里凭空记一笔债）。除此之外一个字都不许动——**被改过的想法，半年后用户分不清哪句是自己说的。**

## 3. 三本库，各写各的

| 库 | 收什么 | 谁写 |
| --- | --- | --- |
| **兼收并蓄** | 灵感、链接、剪藏——一切还没消化的 | 你，经 notectl |
| **以人为本** | 今天的日记 | 你（口述）+ 用户自己 |
| **赛博永生** | 已完成项目提炼出的知识 | 不归本契约管，见 `distill/SKILL.md` |

**绝不往《赛博永生》写口述内容。** 那本库的原料只有一个来源：已完成并归档的项目。往里塞一句没消化的灵感，等于往不可变的事实层里掺沙子。

---

## 4. 人名双链只在日记里发生

脚本只把《以人为本》里**真实存在档案**的人名写成 `[[双链]]`，其余按普通文字记。

**《兼收并蓄》里一个双链都不写。** 人物档案住在隔壁库，跨库双链是一条永远点不开的死链——看上去记上了，实际在那个人的档案、关键事件与待办里一条都不会出现，且不报错。

回执里 `linkedPeople` 为空而用户明显提到了人时，**可以加一句**「库里没有他的档案，先按文字记了，要建档说一声」。**绝不自动建人物档案**——分层、方向这些只有用户知道，猜出来的档案会污染整张人脉网。

---

## 5. 回执

`display` 原样输出，之后**最多再加一行**，且只在用户需要知道时才加（人名没连上、日记是新建的、写进了剪藏而不是灵感集）。没有这类事就只给 display。

```text
✓ 已记进灵感集 · 灵感集.md
```

**禁止**：复述他刚说过的话、汇报调用了哪个脚本、解释你怎么判断的、写「已为您成功记录」这类客套、在没有异常时追问「还需要我做什么」。

---

## 6. 一句话里同时有好几件事

**拆成各自独立的写入，绝不合并。** 例：「今天下午和王磊敲定了大纲，顺手想到定价页可以改」——这是两笔：一条日记、一条灵感，一笔不多一笔不少。先分别完成真实写入，再逐行原样转达各自的 `display`。

---

## 7. 失败分级

| 退出码 | 含义 | 该怎么说 |
| --- | --- | --- |
| 2 | 明确未写入 | 照实说没写进去，并转达脚本给的原因。可以放心重来 |
| 3 | **结果未知** | **禁止重试**。重试可能把同一条写两遍。请用户打开笔记看一眼 |

常见的退出码 2 及话术：

- `theme_required`：今天的日记还没建 → 问一句主题再重发（见第 2 节）。
- 「系统根不存在」/「没找到任何一本装了版次标记的笔记库」：这台机器上可能没装第二版，或者装在别处 → 用 `--root` 指出系统根；仍然失败就如实说明，别猜路径。
- 「以人为本那本库不在它该在的位置」：库被搬走或改名了 → 请用户确认位置，**不要**自作主张改标记文件。
- 「超过单条上限」：通常是语音识别出了问题 → 请他确认要记的是哪一句。

---

## 8. 边界

- 只写三个语义目标（灵感集、剪藏、今天的日记），**命令不接受路径参数**。任何「写到某某文件里」的请求都要如实说明不支持。
- 不做笔记检索。用户问「我上个月记了什么灵感」时，请他在 Obsidian 里搜——那是笔记库的主场。
- 不碰读书划线、概念笔记与 MOC。
- 不主动记录、不扫描、不定时任务；每一条都由用户开口触发。
