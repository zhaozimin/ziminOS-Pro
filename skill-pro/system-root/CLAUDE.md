# ziminOS 三库系统 · 系统根

> 你现在打开的这个文件夹**不是笔记库**，是三本笔记库并排住着的地方。
> 读完这一篇再动手。用户不需要每次都跟你解释这套东西是什么。

## 一、这里有什么

```text
本目录/                ← 系统根，它自己不是笔记库
├── 兼收并蓄/          ← 笔记库 1：进料口。只接住，不加工
├── 以人为本/          ← 笔记库 2：工作台。项目、读书、日历、复盘、人脉、日记
├── 赛博永生/          ← 笔记库 3：成品库。已完成的项目在这里被编译成知识
└── .ziminos/skills/   ← 你的施工契约，日常干活读这里
```

**三本库的真实目录名以磁盘为准，不要照抄上面的名字。** 从第一版升级上来的用户，那本工作台叫什么是他自己当初取的。做法：扫描本目录的直接子目录，读第一份合法的 `.obsidian/plugins/ziminos/edition.json`，它的 `vaults` 给出三本库的目录名。这是布局的唯一事实源，`notectl.py` 也是这么找的。

## 二、用户说什么，你读哪一份

| 他说 | 读 | 结果落在 |
| --- | --- | --- |
| 「记一下：……」「存一下这个链接」「记一下今天：……」 | `.ziminos/skills/capture/SKILL.md` | 灵感与剪藏进《兼收并蓄》，日记进《以人为本》 |
| 「提炼一下」「把新完成的都消化了」 | `.ziminos/skills/distill/SKILL.md` | 《赛博永生》 |

| 「我这半年在某某上想明白了什么」 | 同上（提问） | 读《赛博永生》的知识层作答 |

| 「更新一下 ziminOS」 | `https://gitee.com/ziminzhao/ziminos-pro/blob/main/skill-pro/SKILL.md` | 三本库的程序文件 |

**捕获与提炼的契约就在本地，不要联网去取。** 这套系统对用户的承诺之一是记录过程不联网。

## 三、动手前必须知道的三条

1. **用户的原话一个字都不许改。** 不润色、不总结、不换措辞、不替他补主语、不加标签。清洗、链接排版、人名双链、插入位置、日记骨架全部交给 `.ziminos/skills/scripts/notectl.py`——那是确定性脚本，同输入同结果；你只负责判断「这句话该归哪一类」。
2. **《赛博永生》的 `10-原料/` 只读。** 它是那本库唯一的事实源，连「加个已处理标记」都不行。要记「消化过了」，记进 `90-系统/账本.md`。
3. **不要在系统根里创建任何笔记。** 它不是笔记库；用户在 Obsidian 里打开的是里面那三个文件夹，一次一本。

## 四、每本库的宪法在它自己里面

《赛博永生》根目录有一份 `CLAUDE.md`，那是那本库的 Schema——页面契约、账本格式、命名约定全在里面，**且用户可能改过它，他改过的版本优先于任何契约里的描述**。进那本库干活之前先读它。

## 五、你不确定的时候

三本库的位置、名字、某条命令干什么——**问用户，不要猜**。这套系统里每一次写入都落在他的真实笔记上，猜错一次他不一定当场发现。
