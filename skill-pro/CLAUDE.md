# skill-pro/

> L2 | 父级: ../CLAUDE.md

第二版（付费·三库）交给桌面智能体的全部契约。与 `skill/`（第一版·免费·单库）并列且互不引用——两份安装契约各自完整，因为**装错版次的代价不对称**：把免费版装成三库，用户会得到两本他没买、也不知道怎么用的库。分家而不是加一个分支参数，正是为了让「装哪一版」这件事在文件层面就必须先做选择。

`skill/SKILL.md` 一个字都不许因为第二版而改动。README 首页那段一键安装指令指向的是它，链接已经在外面流传。

## 成员清单

SKILL.md: 三库安装/升级契约。施工源的三种取法都取 Gitee `ziminzhao/ziminos-pro`，按顺序试：发行版上的 `ziminOS-pro-v{版本}.zip`（不需要 Git 与登录）→ 用户手里的包 → `git clone`；Windows 前置四条、禁用 archive 与 raw 拼仓库、只读文件先去属性再删，都来自一份新电脑上的真机复盘。验收清单与交付物对齐：版次标记只有两份（《兼收并蓄》没有 ziminOS 插件，不补），Style Settings 的 `data.json` 是随库配色、必须在。工作区是系统根，A 全新安装、B 单库升级、C 三库日常升级各有严格边界。共享程序与十三个外观片段只从 `vault/` 分发；全新三库默认开启同一份废弃内容语义，升级只对复制前不存在的新片段追加默认启用，不重开已有片段。v0.22.0 起共享程序还包括随两本 ziminOS 库更新、但绝不静默安装的第一方 Eagle 伴侣包；升级验证同时核对主包与 `.eagleplugin` 的版本、SHA-256 和 ZIP 完整性。v0.22.8 起 B/C 回执引导用户在工作台主动预览并确认存量 MOC 数据库迁移，施工阶段仍不改用户笔记。
capture/SKILL.md: 微信快捷收集的单一路由层，只回答「用户有没有要求保存」；一旦要保存，一律调用 `notectl.py inspiration` 追加到《兼收并蓄》的 `灵感集.md`。长内容、链接与「记一下今天」都不再分流，`剪藏/` 明确只归浏览器插件；原话红线、单消息单笔、回执纪律与两级失败语义仍在这里。
distill/SKILL.md: 搬运与提炼契约。搬运归它是因为插件写不到隔壁库；提炼归它是因为那本来就只有 LLM 干得了。它有**两个入口、一条流水线**：出库单驱动（「提炼一下」，清掉全部欠账）与路径驱动（用户粘一条项目 MOC 的路径，只提炼那一个）。两个入口共用同一节搬运、同一节提炼，**入口只决定名单不决定做法**——另起一份契约等于把「怎么拷进原料层、怎么记账」写两遍，而两份迟早只改一份且不报错。路径入口比出库单入口多四道闸，因为出库单上的行是插件写的、天生可信，用户手里的路径却可能指向任何东西：不是容器、还没归档、暂停或放弃（这两种不是结论，必须问）、账本里已经消化过（默默再来一遍正是把知识网写重的路子）。它规定了顺序上一条不许反的纪律：**先提炼再勾出库单**——勾了却没提炼，那份原料会掉进两张清单的缝里，出库单说搬完了、账本说没消化，而没有任何东西会报错。它自己不定义 wiki 的写法，写法归《赛博永生》库内那份 `CLAUDE.md`，且用户改过的版本优先。
system-root/: 两份铺到**系统根**的认路文件（`CLAUDE.md` 与 `AGENTS.md`）。它们回答的是一个此前无人负责的问题：**新会话怎么知道这是什么地方。** 契约躺在 `.ziminos/skills/` 里没有用——没有任何东西告诉一个刚打开这个文件夹的智能体去读它，而智能体打开目录时会自动读的恰恰是这两个文件名。缺了它们，用户每开一个窗口都要重新解释一遍「我这是三库系统、库在哪、你该读哪份契约」，解释不全智能体就开始猜。它们刻意不写死三本库的目录名，只写「扫描直接子目录读第一份 edition.json」——与 notectl 的布局发现同一条路子，因为升级上来的用户那本工作台叫什么是他自己取的。这也是「系统根绝不写 Markdown」那条红线唯一的例外：它们是给智能体的指令，不是给人的笔记，Obsidian 打开的是里面那三个文件夹，永远看不到它们。
scripts/notectl.py: 口述捕获的确定性引擎，零第三方依赖。微信 capture 只获准调用其中的 `status` 与 `inspiration`；`diary/clip` 作为旧版低层兼容入口暂留，但不再属于微信快捷收集契约，尤其不得借 `clip` 写浏览器插件专属的 `剪藏/`。灵感写入的目标路径、清洗、链接搬运与插入位置都在这里，查询在上、标题在下，新条目永远紧贴 `# 灵感集`；people 名单同时排除 `MOC-人脉.md` 与存量 `人脉MOC.md`，与插件改名保持兼容。
scripts/test_notectl.py: 全仓库第一个自动化测试，35 条。落在这里不是偶然：notectl 是直接往用户笔记里写字的代码，而它的核心全是零 I/O 的纯函数，天生可以在没有笔记库、没有 Obsidian 的环境里逐字节验证。每一条用例都对应一个真实会发生、且**不会报错**的错误。`python3 test_notectl.py` 直接跑，不需要装任何东西。

## 布局发现

notectl 不读配置也不问用户库在哪：安装契约把它放在 `系统根/.ziminos/skills/scripts/`，往上数三层就是系统根。工作目录会变，脚本的位置不会。拿到系统根后扫描它的直接子目录，读第一份合法的 `edition.json` 得出三本库的名字——**刻意扫描而不是写死「以人为本」**，因为从第一版升级上来的用户那本库叫什么是他自己当初取的。
