# 赛博永生 · 搬运与提炼

这份契约管两件事：**把已完成的项目从《以人为本》搬进《赛博永生》**，以及**在《赛博永生》里把它编译成知识**。

搬运之所以由你干而不是插件干：Obsidian 的 vault API 被沙箱锁在本库内，插件写不到隔壁库去。插件只在本库记一笔「欠了这一份」，剩下的归你。既然提炼本来也只有你干得了，就一次进门把两件事一起做完。

**动手之前先读《赛博永生》根目录的 `CLAUDE.md`。** 那是这本库的宪法，页面契约、账本格式、命名约定全在里面，且用户可能改过它——**他改过的版本优先于这份契约里的任何描述。**

---

## 零、两个入口，一条流水线

搬运与提炼的做法只有一套（第三、四节），区别只在**这一次要处理哪些项目**：

| | 入口 A · 出库单驱动 | 入口 B · 路径驱动 |
| --- | --- | --- |
| 用户怎么开口 | 「提炼一下」「把新完成的都消化了」 | 甩来一条 MOC 路径，说「提炼这个」 |
| 处理范围 | 出库单上**全部**没勾的行 | 他指的**那一个** |
| 项目从哪来 | 插件在归档那一刻记下的事实 | 他手里的路径 |
| 适合什么时候 | 攒了几个，一次清完 | 刚归完档就想看结果；或让某个项目重新消化一遍 |

两个入口都走完第三节（搬运）与第四节（提炼），一个字不差。**入口只决定名单，不决定做法。**

用户没指名道姓就走 A：出库单是插件写的，比你去归档目录里翻要可靠。他给了路径就走 B，这时**不要**反过来劝他用出库单——他指名的那个项目可能压根不在单上（第一版时期归的档，或者他手建的），也可能是他明知消化过、就是要再来一遍。

---

## 一、先认路

三本库的位置从版次标记读，不要猜：

```bash
cat "<系统根>/以人为本/.obsidian/plugins/ziminos/edition.json"
```

它的 `vaults` 给出三本库的目录名。从第一版升级上来的用户，`vaults.human` 是他自己当初取的名字，不一定叫「以人为本」。

---

## 二、点名单

### 入口 A：读出库单

`<以人为本>/90-system/赛博永生出库单.md`。每一行是一个已完成并归档的容器：

```markdown
- [ ] 2026-08-16 14:22 · 项目 · [[定价改版]] · `04-archives/定价改版` · UID 20260301091500
```

**没勾的才要搬。** 勾了的说明搬过也提炼过了。

出库单不存在或一行没勾的，说一句「没有新东西要搬」就完事，不要去归档目录里自己翻——那张单子是插件在归档那一刻记下的事实，比事后扫描目录可靠。

### 入口 B：认那条路径

用户复制路径的方式有好几种，四种形态都得认得出。**先把它化成「库内相对路径」**，那是后面每一步唯一认的形式：

| 他粘过来的 | 怎么化 |
| --- | --- |
| `04-archives/定价改版/MOC-定价改版.md` | 已经是库内相对路径，直接用 |
| `/Users/…/系统根/以人为本/04-archives/定价改版/MOC-定价改版.md` | 砍掉 `<以人为本>/` 这段前缀 |
| `obsidian://open?vault=以人为本&file=04-archives%2F定价改版%2FMOC-定价改版` | 取 `file` 参数，URL 解码，补回 `.md` |
| `[[MOC-定价改版]]` | 双链只有文件名。在 `<以人为本>` 里搜同名 `.md`，**搜出多个就把候选列出来问他要哪个**，不要挑第一个 |

化不出来就停下来问，不要拿一条猜出来的路径去拷文件。

**再从这条路径反推项目文件夹**：

1. 路径指向一篇 `.md` → 项目文件夹是它的**上一级目录**。
2. 路径指向一个目录 → 那就是项目文件夹本身。
3. 拿到文件夹后，**回头在里面找那篇 MOC**：文件名是 `MOC-*.md`（V3 起）或与文件夹同名的 `.md`（存量库）。找 MOC 不能靠他粘的那篇——他可能随手复制的是项目里某张卡片的路径，卡片的 `type` 和 `UID` 都是空的。

### 入口 B 的闸门

从 MOC 的 frontmatter 里读 `type`、`status`、`UID`，逐条验，**任何一条不过就停下来说话，不要擅自搬**：

| 读到什么 | 怎么办 |
| --- | --- |
| `type` 不是 `project` 也不是 `book` | 这不是一个容器。告诉他你看到的是什么，问他是不是指错了文件 |
| `status: active` | 项目还没归档。**别搬**——告诉他先在 Obsidian 里按「完成项目」，插件会把它移进归档目录并记上出库单 |
| `status: paused` / `dropped` | 搬之前**必须问**。暂停是「还没想好」，放弃是「明确不要了」，两个都不是结论；当成知识素材会让这本库长出一堆讲「我当时没做完」的页。他坚持就照办，是他的库 |
| 没有 `UID` | **不能搬。** 没有 UID，这份原料在《赛博永生》里对不上号，重复归档还会长出第二页讲同一件事。让他在 MOC 里补一个 UID（14 位时间戳，形如 `20260301091500`）再来 |
| `status: done` 且 UID 齐全 | 放行 |

**最后一道：查账本。** 拿这个 UID 到 `<赛博永生>/90-系统/账本.md` 里搜一遍。已经有消化记录的，说清楚「这个在 X 月 X 日消化过了，触及了哪几页」，问他是要重新消化（同一 UID 的新版本，按第四节更新已有页而不是新建）还是搞错了。**别默默再消化一遍**——那正是把知识网写重的路子。

---

## 三、搬运

对名单上的每一个项目：

```bash
cp -R "<以人为本>/<项目文件夹>" "<赛博永生>/10-原料/<项目名>/"
```

三条纪律：

- **是拷贝不是移动。** 用户的归档目录里那一份必须原样留着——那是他的东西，这边只是取了个副本。
- **目标已存在就不要覆盖。** 说明同一个项目搬过第二次（重新开始后又完成了）。这时把新副本放成 `<项目名>（UID）/`，两份都留着，让提炼那一步去比对差异。
- **拷完不许再改它一个字节。** 原料层是这本库唯一的事实源，加个 `ingested: true` 也不行。要记「消化过了」，记进账本。

拷完顺手确认一下 `10-原料/<项目名>/` 里那篇 MOC 在，且 `UID` 字段没在拷贝中丢失——「待提炼」那张清单认的就是它。

---

## 四、提炼（消化）

对每一份新原料：

1. **先读 `<赛博永生>/20-知识/索引.md`**，知道这张网上现在有什么。跳过这一步的结果是长出一堆重复页。
2. 通读原料：MOC、卡片、日记里提到它的地方。
3. 按 `CLAUDE.md` 的页面契约写页。**一份原料通常牵动十几页，不是一页。**
   - 项目里的**概念**（定价策略、冷启动方法）→ `20-知识/概念/`
   - 项目里的**人、产品、公司** → `20-知识/实体/`
   - 你从中读出的**判断** → `20-知识/结论/`
   - 这份原料本身讲了什么 → `20-知识/来源/`
   - 已有的相关页要**更新**并互相链接，不是各写各的。
4. 遇到与已有页说法冲突的，**标出矛盾，不要擅自采信新的**。旧结论可能仍然成立，只是条件变了。格式照 `CLAUDE.md`。
5. 更新 `20-知识/索引.md`。
6. 往 `<赛博永生>/90-系统/账本.md` 追加一行：

```markdown
- 2026-08-16 19:33 · 消化 · 定价改版 · UID 20260301091500 · 触及 [[年付定价]]、[[王磊]]
```

**那个 UID 是硬要求。** 这本库的「待提炼」清单就是拿原料的 UID 到账本里比对算出来的——UID 不写，这份原料会永远显示成没消化过，而下一次提炼会把同一份东西再消化一遍，知识层也跟着重一遍。

标记写中文的「消化」。插件读账本时两种都认，但新写的一律用中文——这本库里用户看得见的每一个词都是中文，账本没有理由是例外。

### 判据：只碰了一个文件就是没做完

一份原料只写一页摘要就收工，是这套东西最常见的失败方式。那样得到的是一堆互不相干的读后感，不是一张网。

### 用户改过的地方不许覆盖

知识层是机器写的，但人随时可以改。碰到同一页时：**人加的段落、人改的措辞一律保留，新信息追加而不重写整页；确实要改人写的句子，先说，别直接动手。**

他改那一句，是因为机器写错了或写得不是他的意思。第二次把它改回去，等于告诉他「你的修改没用」——而他不会立刻发现。

---

## 五、收尾：勾出库单

提炼完之后，把出库单里对应那一行的 `- [ ]` 改成 `- [x]`。**按 UID 定位那一行**，不要按项目名——项目会重名，UID 不会。

顺序很重要：**先提炼、再勾。** 勾了却没提炼，那份原料会掉进两张清单的缝里——出库单说搬完了，账本说没消化，而没有任何东西会报错。

入口 B 有一种情况是**单子上根本没有这一行**：第一版时期归的档、手建的项目、或者他要求重新消化一个早就勾过的。这时**不要补写一行再勾掉**。出库单回答的是「插件记下的移交欠账还剩几笔」，往里塞一条它没记过的，等于伪造它的记账。账本里已经有了 UID，「待提炼」自然归零，两张清单各自都还是真的。

---

## 六、提问（Query）

用户问「我这半年在定价上想明白了什么」时：

1. 读 `20-知识/`，不是 `10-原料/`。原料只在知识层答不上来、需要核对原话时才翻。
2. 回答带出处，指明是哪几页。
3. **答得好的要回填**成一页结论页，并往账本追加一行 `提问`。一次值得的探索如果只留在对话里，下次还得从头再来。

---

## 七、体检（Lint）

**只在用户明说「体检一下」时才跑。绝不做成定时任务，绝不顺手跑。**

查五样：矛盾、孤儿页（没人链进来）、缺页概念（被反复提到却没有自己那一页）、过期结论（引用的原料后来有了新版本）、断链。

**只报告，不擅自修。** 报完等用户点头再改。往账本追加一行 `体检`。

---

## 八、红线

- **不改原料。** `10-原料/` 只读，包括「加个标记」。
- **不移动、不删除用户在《以人为本》里的任何东西。** 你只读它的出库单和归档目录，唯一的写是把那一行勾上。
- **没归档的项目不搬。** `status: active` 一律退回，让他先在 Obsidian 里按「完成项目」。
- **同一个 UID 不擅自消化第二次。** 账本里查得到就先问。
- **不往出库单里补写它没记过的行。**
- **不联网。** 这本库里的一切从原料编译而来。
- **不定时、不后台。** 消化 / 提问 / 体检全部由用户开口触发。
- **不删知识页。** 结论过期了就标注过期并说明为什么——「我曾经这么想过，后来发现不对」本身就是知识。
- 先提炼再勾出库单，顺序不许反。
