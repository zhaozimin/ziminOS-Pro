基线 v0.39.0，修复版 v0.39.1。审计包括全仓库构建与自动回归、安装/发布通道检查、依赖安全扫描；人工重点审阅 core 编辑欠账、review 日记历史和 projects 容器改名的数据与异步边界。未将自动检查称作逐行审完每份上游资产。设计事实源见规格 V2 §75。

## 已修复的问题

| 影响 | 触发条件与原错误 | 修复结果 |
| --- | --- | --- |
| 用户文本丢失 | 日记托管区里加一行备注或手改活动格式，下一次记账只保留能解析的活动，删除其余行 | 未识别的原始行逐字保留，只归并活动与删除模板占位 |
| 事实误分类 | 修改的笔记路径或别名含 🆕，解析器在全行找图标，把修改读成新建 | 只用行首捕获的图标判断类型 |
| 跨日丢账 | 同一篇一直开着跨过午夜，两个日期的编辑只存最后一个时间戳 | historyGroup 按事发日归并，离开后逐日结算 |
| 重启丢账 | 尚未记入日记时，updated 或排版改变源文件 mtime；旧恢复规则将历史作废 | 最新状态回写与历史事实分开，历史仍按原时刻补记；旧数字格式兼容 |
| 失败丢账 | 日记创建失败返回 null，或写日记抛错，被视作已结算而撤销 | 失败项保留到下次事件或启动；已成功项独立撤销，不轮询重试 |
| 相对链接断链 | 把 Markdown 相对目标改成没有正确源坐标的整条库内路径 | 从移动后的源目录生成相对目标，逐段 URI 编码，保留锚点/标题 |
| 漏改链接 | 尖括号链接目的地带空格，正则先匹配非空白分支而截断目标 | 尖括号目的地完整优先匹配 |
| 误改示例 | 全文正则把代码块或行内代码中的双链示例也当成引用 | 只处理公开元数据证明的正文引用范围；YAML 属性区另按公开范围处理 |
| 卡片展示名被篡改 | 卡片别名恰好等于旧项目名，误套用 MOC 更名规则 | 默认别名随身份改写只适用于 MOC，卡片别名保留 |
| 过期同意 | 预览期间无链接卡片正文变化，原计划只快照要改链的笔记而未发现 | 容器内全部 Markdown 原文进入确认快照 |
| 身份偷换 | 同路径 MOC 或子文件换成相同字节的新对象，文本/路径指纹仍相同 | 确认同时比较文件对象，写盘前再比对路径/对象/正文 |
| 并发重名 | 预览期间其他 PARA 根出现新重名，二次计划只查本根目标 | 两次计划都核对四个 PARA 根的名称占用 |
| 部分搬移 | 容器内部已有一篇与新 MOC 同名的文档，搬完文件夹才发现冲突 | 首次动盘前拒绝目标 MOC 名占用 |
| 回滚短路 | MOC 名恢复抛错，同一个 try 内的目录恢复也被跳过 | 文本/MOC/目录逐项独立恢复，汇总全部失败项 |
| 缓存迟到 | 正文已保存，链接缓存还缺席或偏移与原文不符，可能漏改链后仍搬目录 | 命令停止并明确提示等待元数据同步后重试 |
| 不安全输入 | 新名包含双引号等字符，可能破坏 Windows 路径或双引号 YAML | 输入阶段拒绝，并对空白再次校验 |

相对路径、空格目标、卡片别名、手写行与图标分类的新增测试先在旧代码上复现失败。历史欠账四个基本场景、改名运行时五个确认/回滚场景同样先验证为红，再修复；新增的兼容、正常提交与并发续写用例用于补齐边界。

## 依赖安全

npm 镜像审计接口返回 404/NOT_IMPLEMENTED，改用 npm 官方 registry 才获得有效结果。原依赖树报 3 个受影响条目，来自两条公告：

- DOMPurify 3.4.15 → 3.4.16，修复 [DOMPurify 官方安全公告](https://github.com/cure53/DOMPurify/security/advisories/GHSA-p98j-92pf-mc4p)。它是 jsPDF 的可选 HTML 依赖；本产品不调用 jsPDF.html，仍锁定补丁版本。
- Moment 2.29.4 → 2.31.0，修复 [Moment 官方安全公告](https://github.com/moment/moment/security/advisories/GHSA-4p3w-j4w9-5jqw)。obsidian npm API 包连带被标为受影响；overrides 修复开发/测试树，插件运行时仍从 Obsidian 取 Moment，不声称改变了宿主版本。源码没有把外部输入送进 locale 的路径。

补丁版本在 package.json 中精确锁定，并同步 lockfile 的地址与 integrity。复扫全依赖为 0 项漏洞。
