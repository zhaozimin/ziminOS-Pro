# 插件代码审计修复报告 · 2026-09-19

本次审计始于 v0.35.3 工作区，修复随 v0.35.4 交付。审查覆盖发布与打包脚本、全新安装器、插件全部源码、Eagle 伴侣与三层 GEB 文档。四处缺陷里两处在**交付链**上、一处是**安全债**、一处是文档与代码说反话——共同点是它们都不在写错的那一行报错，也都不会被既有测试拦下。实现契约见设计规格书 V2 §66。

## 已修复的问题

| 影响 | 触发条件与原错误 | 修复位置与结果 |
| --- | --- | --- |
| 交付中断 | 中文 locale（`zh_CN.UTF-8`）下打第一版分发包，zip 与 SHA 都已产出，最后一步生成发行说明时报 `size�: unbound variable` 中止；另一处让「连不上第一版仓库」这句人话变成脚本崩溃 | `make-v1-package.sh:70/:256` 的变量改用 `${name}` 划界。v0.35.1 已在 `publish-v1.sh` 修过同一个 bug，但回归只钉住那一个**文件名**——`tests/regression.mjs` 那条因此改成扫全部 `*.sh` 并报出文件、行号与被吞的变量，另加扫描范围失效的下限断言 |
| 安装可靠性 | 全新安装自检不过时回滚删不掉（Windows 文件占用、POSIX 父目录不可写），`remove_tree` 静默返回、`roll_back` 不问结果、`main` 无条件写 `rolled_back: true`；残留的 `.obsidian/plugins/ziminos` 让下一次运行判成 `upgrade`，智能体去升级一个从未装成的库 | `installer/ziminos_install.py` 的 `remove_tree` 改以**磁盘事实**为判据并返回结果，`roll_back` 交出撤不掉的名字，`main` 两处失败出口收口到同一份 `undo()`，结果文件多出 `rollback_leftovers` |
| 安装中断 | 回滚途中只要有一层目录读不进去，`rmtree` 会把 `os.open` 交给错误处理器，而无条件的 `func(target)` 少一个 `flags` 参数抛 **TypeError**（非 `OSError`）——穿过重试从 `roll_back` 抛出，**结果文件根本写不出来**、退出码不是约定的 30、工作区留着半个库 | 同文件 `clear_readonly` 按平台给权限（`S_IWRITE` 在 POSIX 上是 `0o200`，读与进入的权限一起没了，比原来更删不掉），重放失败一律吞掉并交给磁盘校验兜底 |
| 契约一致性 | 两份安装契约的 `failed` 行写着「脚本已经撤掉了它写进文件夹的东西」——这句话在撤不干净时不是事实，而智能体正是照它决定下一步 | `skill/SKILL.md` 与 `skill-pro/SKILL.md` 按 `rolled_back` 分两条路，并点名 `rollback_leftovers`；代码说真话而契约还在替它打包票，等于没修 |
| 凭据安全 | 微信读书登录态住在 `data.json`，靠 `.gitignore` 挡住 git——挡得住版本库，挡不住 Obsidian Sync、iCloud、备份与打包转发；而同一仓库里只能碰本机资源库的 Eagle 配对令牌反而用着官方 `SecretStorage` | `books/sourceWeread.ts` 把它搬进 `SecretStorage`（`App.secretStorage` 自 1.11.4 公开，本插件 `minAppVersion` 1.13.0）。`wereadCookie()` / `storeWereadCookie()` 是唯一出入口，设置页经 `SettingActions.isWereadConnected` 注入问状态；老库由 `migrateWereadCookie` 在装配时搬走，**搬不过去就原样留着**，绝不在搬运途中弄丢学员的登录态 |
| 文档正确性 | `export/decorate.ts` 的 `linkRegions` 文档块写着「坐标走 offsetLeft/offsetTop 链」，而实现走的正是 `getClientRects()` 加 scale 还原——v0.32.0 合并两套算法时留下的旧话，与同文件 `pushRects` 的注释互相打脸 | 改写为实际做法与它的理由 |
| 文本正确性 | `books/douban.ts` 的 `clean()` 链式还原实体，`&amp;` 排在 `&lt;` 之前，`&amp;lt;` 被二次解码成 `<`；那段文字接着写进 Markdown，而 Obsidian 认 HTML | 改为一趟扫描加映射表，让二次解码在机制上不可能发生，而不是靠「记得把 `&amp;` 放最后」这种约定 |

## 交付与验证边界

不新增运行依赖，不改变笔记格式，不改变两版装配入口。`skill/SKILL.md` 本轮有改动，动机是「那行字已经不是事实了」而不是为第二版让路——判据与 v0.17.0 改克隆地址时同源。

本轮未做真机验收。两处需要在测试库里实走：凭据搬家（扫码连接 → 断开 → 从老库升级，确认登录态既搬得过去也丢不了），以及安装器在真 Windows 上的回滚（`install.ps1` 至今未上过真机，66.2 的三处修复在 Windows 上只有静态回归与 POSIX 等价场景护着）。`remove_tree` 三次重试仍可能撤不干净——那是宿主占用的事实，本轮改的是**把它说出来**而不是保证删得掉。
