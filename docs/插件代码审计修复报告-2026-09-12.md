# 插件代码审计修复报告 · 2026-09-12

本次审计始于 v0.32.0 工作区，相关修复现已整合进 v0.35.0。审查覆盖插件核心、笔记写入与归档、导出和 Eagle 两端；新增行为测试复现并锁定了原有测试未覆盖的并发、异步失败和生命周期问题。

## 已修复的问题

| 影响 | 触发条件与原错误 | 修复位置与结果 |
| --- | --- | --- |
| 数据完整性 | 待办视图显示后在源日记插入另一条未完成任务，旧行号会勾掉另一项 | `core/markdown.ts`、`vaultIndex.ts`、`table.ts` 与 `contacts/personViews.ts` 传递并核对原行快照；冲突不写回，I/O 失败明确提示 |
| 数据完整性 | 两个项目同时归档，出库单的读后整篇覆盖会丢掉一笔，或覆盖用户新备注 | `eternal/export.ts` 在同一次 `Vault.process` 中判重并追加；首次建单竞争复用现有笔记 |
| 数据完整性 | 空白周期笔记在套模板等待期间出现新输入，旧空态检查仍允许覆盖 | `review/periodic.ts` 在最新正文内再次判空；自动归位等待结束后重验身份和空态；同日并发创建复用已建笔记 |
| 数据完整性 | 同项目同时执行两次状态流转，后一次失败回滚可能把第一次已完成的归档撤回 | `projects/transitions.ts` 从确认到收尾按目录对象互斥；首次写入前核对目录/MOC 身份与目标空位，回滚不接管替代对象 |
| 数据完整性 | Eagle 全部上传失败后，占位符被删除，原选中文字也随之丢失 | `eagle/transfer.ts` 保存并恢复原选区；路由解析在放置占位符之前完成 |
| 文件身份 | macOS 文件路径末尾空格被两端 `trim`，存在近似同名文件时会导入错误文件 | `eagle/transfer.ts` 与伴侣 `service.js` 逐字传递文件路径 |
| 资源库身份 | Eagle 操作排队或等待 API 时切库，入口的旧鉴权仍被后续操作沿用 | 伴侣在队列执行及异步边界再次校验配对库；检测变化后停止后续创建、导入、读取、定位和原生深链操作 |
| 显示完整性 | 普通图片节点被移动/移除时，Eagle 全局监听误删其 `src` | `eagle/render.ts` 只清理属于 Eagle 的图片；同批 DOM 变更先统一释放，再重新水合复用节点 |
| 索引正确性 | 磁盘已更新而元数据尚未到达，空列表被同一 mtime 长期缓存；旧读盘完成时又可能冒充新 mtime | `core/vaultIndex.ts` 同时核对读盘前的时间与 listItems 快照，异步期间事实变化则不缓存 |
| 操作可靠性 | 两次操作同时创建共同父目录，后到的操作因“已存在”失败 | `core/folders.ts` 只在现场确为目录时按竞争成功处理，仍传播真实 I/O 错误 |
| 链接正确性 | 汇总视图把双链的标题/块锚点丢掉，转义别名可能残留反斜杠 | `core/table.ts` 保留完整跳转目标，同时支持本页锚点与转义别名 |
| 导出生命周期 | 渲染正文失败时 ExportPaper 尚未返回，外层无法释放已建舞台与组件 | `export/paper.ts` 在返回前自行清理，返回后交出幂等释放函数；组件卸载抛错也移除舞台，编排层收口清理异常 |
| 导出生命周期 | 预览关闭后，系统选图或保存框迟到的回调重新排帧、再次处理已释放纸张 | `export/modal.ts` 关闭即撤销异步回调的写回权，取消保存框仍保留预览供重试 |
| 导出一致性 | 系统保存框打开期间修改格式，保存路径扩展名与实际内容可能不一致 | 保存框与最终交付使用同一个点击时的风格快照 |
| 导出一致性 | 重复执行导出命令产生多张活动纸，全局主题恢复相互覆盖 | `export/exporter.ts` 同一插件一次只运行一条导出流程，完成、取消或失败后释放占用 |
| 升级兼容性 | 旧设置只含页眉/页脚链接，新增开关的默认推导忽略链接，升级后内容消失 | `core/exportStyle.ts` 把链接纳入旧值的可见性推导，显式关闭继续生效 |
| 导出尺寸 | 点击 A4/A3 预设只改变按钮状态，实际纸宽与高度仍用旧值 | `export/panel.ts` 将预设的 `width/height` 明确映射到风格的 `pageWidth/pageHeight`，实际点击控件的回归验证尺寸生效 |

## 交付与验证边界

源码、模块 L2/L3、全局地图与设计规格同步。构建使用工作区已有依赖，不新增运行依赖，不改变笔记格式和两版装配入口。本轮成果随 v0.35.0 进入发布流程。

本轮未把改动部署进用户的真实笔记库，未进行 Obsidian/Eagle 真机交互验收。需要在测试库复核真实导出图片/PDF 的版面、系统保存框、分栏任务勾选和 Eagle 附件粘贴。Eagle 已经受理的单个 API 不支持由桥接层原子撤销；切库检查保证发现变化后停止后续操作，不能承诺撤销宿主已经执行的动作。
