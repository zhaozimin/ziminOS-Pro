01 / Verdict

核心结论

本轮问题不是「某个按钮不灵」，而是多个静默错误：插件可能把取数失败说成没有划线、把刚写入的成功说成「已是最新」、把同名人物链到错档案，或在用户重新打开笔记后仍整篇重写。这类错误没有明显崩溃，却会损伤用户对知识库的信任。

结论：代码修复完成，已产出新分发包 v0.14.0 共用代码与 v0.16.0 专业版源码均已同步修复；新包已通过构建、回归、交付物清单、中文路径编码与 SHA-256 校验。

ID级别缺陷 / 根因核心修复主要落点状态
F-01P1移动端声明可用，但 Apple Books / Kindle 在模块顶层静态引入 Node 内建模块，加载阶段即可失败。Node 能力收入桌面守卫后的惰性适配器，探不到时整个来源降级，不影响插件加载。sourceAppleBooks.ts
sourceKindle.ts		已修复
F-02P1书源异常被空 catch 吞掉，取数失败与确实零划线无法区分。各来源独立失败，失败也返回带中文说明的零划线结果，调用方必须向用户说实话。sources.ts
sourceKindle.ts		已修复
F-03P1Markdown 整理固定按 LF 重组，CRLF / CR 文件会出现整篇伪差异。输入时识别原换行约定，内部统一 LF 处理，出口恢复原 CRLF / CR / LF。markdownStyle.ts已修复
F-04P1排版计划排队后，用户若重新打开目标笔记，旧任务仍可整篇写盘。读盘后和 vault.process 提交时都重新检查实时活动文件；被用户打开的笔记回到待离开集合。formatter.ts已修复
F-05P2划线写入后才对新文本重算合并，结果必然倾向「已是最新」，成功被误报。保留 vault.process 回调中那次真实 MergeOutcome，区分新划线、仅补想法与确实无变化。readBook.ts已修复
F-06P2微信读书内存令牌未绑定生成它的 Cookie，重连后可复用旧令牌。缓存同时记住 Cookie；Cookie 变化、401、断开或卸载都使令牌立即失效。sourceWeread.ts已修复
F-07P2扫码登录没有总超时、重复会话互斥与插件卸载清理，轮询可长期悬挂。增加 120 秒上限、单活跃会话、关窗/超时/加载失败统一收口，并在主插件卸载时注册清理。sourceWeread.ts
main.ts / settings.ts		已修复
F-08P2视图的旧异步渲染晚于新渲染返回时，会把新 DOM 覆盖回旧数据。每次渲染分配代号并画在离屏容器；只有最新且未卸载的一代能原子提交。codeblock.ts已修复
F-09P2本年度在途项目按年末计算持续时长，把尚未到来的日子计入已执行时间。在途耗时统一截止到今天；历史年份继续明示当前状态不等于历史快照。projectViews.ts已修复
F-10P2初始化中途失败会留下插件自己的半成品，下次又被「非空库」检查拦住。空库检查排除全部已知种子；确定性骨架完成后先提交初始化事实，再执行可选首项目引导。setup/init.ts已修复
F-11P2人情账本与 principal/client 关系只写 basename，同名人物存在静默错链。身份改用完整库内路径，basename 只作显示别名，兼顾消歧与界面可读性。recordFavor.ts
createContainer.ts		已修复
F-12P2专业版出库单对整行使用可见字符串 split，项目名或路径含「 · 」时字段错位。保留人类可读的旧格式，解析改从 UID、反引号路径和前两个固定边界定位，兼容旧清单。eternal/manifest.ts已修复

03 / Architecture

修复后的系统边界

加载边界

平台不具备的能力不在 import 阶段触发。移动端可以加载整个插件，只是桌面书源自然不可用。

读取边界

「没有数据」与「读取失败」在类型与呈现上保持不同。某一书源失败不拖垮其他来源，但也不再沉默。

写入边界

计划写入不等于获得永久授权。真正落盘前再检查用户是否已重新打开目标；旧异步代不得覆盖新代。

身份边界

显示名不再兼任主键。书用通过校验的 ISBN，人物用完整库内路径，出库项目用 UID 与结构边界。

文档边界

L3 文件契约、L2 模块地图、L1 项目定义与设计规格已同步；新增 tests/CLAUDE.md 使测试也进入 GEB 地图。

06 / Quality

品味自检

  • KISS：没有为平台差异新建第二套书源，只把 Node 能力收到现有模块的桌面边界内。
  • SRP / DIP：微信读书认证生命周期仍在 books 模块，设置页只经 SettingActions 注入连接与断开能力。
  • DRY：划线合并不再写后重算；同一次真实写入的结果同时驱动数据与提示。
  • OCP：书源失败继续使用现有 SourceHit.note 扩展点，其他来源和合并内核无需改写。
  • 数据优先：时间、身份、换行符和出库单都先保护事实，再考虑展示与便利。
07 / Residual Risk

仍需真机验收的边界

头部自动化已全绿，但以下三类行为依赖 Obsidian / Electron / 本机应用的真实运行时，不能用纯 Node 测试伪装成已完成：

  • iOS / Android 上实际启用插件，确认设置页、视图和非桌面功能正常。
  • Electron 扫码窗口的超时、重复点击、断开后重连与插件卸载。
  • 排版防抖期间快速切回笔记，以及真实 Apple Books WAL / Kindle 卷宗的拔插、权限与读取失败。
工程状态：v0.16.0 的真实源码位于一个既有的辅助工作树，且该工作树原本已有大量未提交变更。本轮已保留那些内容并产出可验证分发包，但建议下一步将 v0.16 源码正式收入受版本控制的分支，避免「只有包、源码在隐藏工作树」成为新的事实源飘移。
